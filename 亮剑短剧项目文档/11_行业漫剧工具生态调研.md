## 二、六大核心能力对标

### 2.1 角色一致性方案

| 方案 | 工具 | 原理 | 成熟度 |
|------|------|------|--------|
| Character Cameo (角色 ID) | Sora 2 | 上传参考照 → 获得可复用 ID → 场景中引用 | 高（商业） |
| 多参考图 + style reference | Veo 3.1 | 3~5 张不同角度参考图锁定角色 | 高（商业） |
| **角色卡 + DNA 锁定** | Catimind | 角色卡包含三视图+表情变体+服装，跨项目复用 | **极高** |
| **8 维特征 DNA + Vision Auto-Retry** | Wind Comic | VLM 提取面部8维特征 → 注入每帧 prompt → <75分自动重生成 | **最高（开源可参考）** |
| IP-Adapter + FaceID | ComfyUI 方案 | 特征编码固定向量，多角度保持身份 | 高（需本地部署） |
| 多图输入锁定 | 即梦AI / 巨日禄 | 上传多张 → 系统自动提取特征 | 中 |

**可借鉴**: Wind Comic 的 **Character DNA** 机制——用 VLM 提取角色特征向量，在每帧生成时作为约束注入，生成后再做 Vision Audit 校验相似度，低于阈值自动重试。

### 2.2 资产复用体系

| 方案 | 工具 | 原理 |
|------|------|------|
| **角色卡/场景库/风格包/镜头模板库** | Catimind | 四类资产独立管理，跨项目复用 |
| @资产引用 + 编译预览 | Wind Comic | 在 Prompt 中用 @ 语法引用资产，编译时检查完整性 |
| 资产上传匹配 | 巨日禄 | 分镜阶段上传角色/场景/道具，系统自动匹配 |
| 角色/场景/道具 标准化工作区 | Dramily | 统一管理工作区，所有镜头引用相同资产 |

**可借鉴**: Catimind 的 **资产分层复用体系**——角色卡（三视图+多表情+服装变体）、场景库（多角度+色调参数）、风格包（预设色彩/光照/线条组合）、镜头模板库（已验证的高成功率镜头构图）。核心思想：**建一次，用一百次**。

### 2.3 流水线/工作流设计

| 模式 | 工具 | 设计 |
|------|------|------|
| **多 Agent 协作** | Wind Comic | 8个专业 Agent（编剧/导演/制片/角色设计/分镜师/一致性/口型/剪辑），每个有严格交接合约 |
| **6 阶段流水线** | Micro Drama Toolkit | Foundation → Cast → Story → Production → Assembly → Monetize |
| **分镜审批流程** | Topview / Dramily | 分镜确认后才消耗视频 credits |
| **低精度→高精度** | Catimind | 先 480p 批量预览确认节奏→仅 20% 关键镜头精修 |
| **对话式逐步确认** | Zopia | 每步产物用户确认后才进入下一步 |

**可借鉴**: 
- Catimind 的 **Preview-Then-Refine**：480p 低精度预览整集 → 确认节奏构图 → 仅 20% 关键镜头精修 720p/1080p。这个策略可以直接用到当前项目中——先让用户快速确认分镜和 prompt，再花算力生成高精度视频。
- Wind Comic 的 **分镜审批后才生成视频**：防止用户浪费算力在未确认的分镜上。

### 2.4 AI 校验/质量门禁

| 方案 | 工具 | 原理 |
|------|------|------|
| **Style Vision Audit** | Wind Comic | 调色板/光照/色温/纹理综合评分，<70 自动重生成 |
| **Cameo Vision Retry** | Wind Comic | 角色相似度评分，<75 自动重生成 |
| **Pacing Audit** | Wind Comic | 冲突分数检测 + 反转次数 + 悬念检测 |
| **Polish Pro 剧本审计** | Wind Comic | 剧本阶段检查 AIGC 适配度、hook 强度、三幕结构 |
| 分镜审批门禁 | Topview/Dramily | 消耗 credits 前必须确认分镜 |

**可借鉴**: Wind Comic 的 **Vision Audit + Auto-Retry** 闭环。生成后自动评分，低分自动重试。这个逻辑可以直接应用到当前项目的关键帧生成和视频生成阶段。

### 2.5 数据血缘/回溯

| 方案 | 工具 | 原理 |
|------|------|------|
| **阶段 rerun** | Wind Comic | 任意单阶段可重新运行，不污染其他阶段 |
| **Cost observability** | Wind Comic | 逐项目逐阶段成本归属 |
| 版本对比 | Catimind | 交付包支持版本对比和归档 |
| 数据血缘 | — | 全行业未见深度实现 |

**可借鉴**: Wind Comic 的**单阶段 rerun**机制。我们当前项目中的 `visualPromptSource: 'auto' | 'manual'` 思路与此一致——标记某字段是否由用户编辑，AI 只覆盖 auto 字段。

### 2.6 视频生成策略

| 方案 | 工具 | 原理 |
|------|------|------|
| **首帧为王** | All | 首帧质量决定全局一致性 |
| **以帧定调** | 行业共识 | 首帧用高精度模型，后续用快速模型 |
| **分解启发法 (Decomposition Heuristic)** | Hailuo AI Guide | 复杂动作拆为 3 个简单镜头，通过率提升 40-50% |
| **首尾帧插值 + 中间关键帧** | Sora 2 / Veo 3.1 | 支持 3~5 关键帧精确控制中间过程 |

**可借鉴**: **分解启发法**。复杂镜头（如"冲锋+射击+爆炸"）一次生成成功率极低，拆为 3 个简单镜头分别生成再拼接，通过率从 ~30% 提升到 ~70%。

## 三、与当前项目最相关的 5 个借鉴点

### 3.1 借鉴 Catimind 的资产复用体系

当前项目有 `Character` 和 `Scene` 资产，但**没有分层复用机制**。

**参考方案**：
```
角色卡 = 三视图 + 5个核心表情 + 2套服装变体 + 参考色卡
场景库 = 大全景 + 多角度中景 + 色调参数
风格包 = 预设胶片质感/光影参数/色彩方案
镜头模板库 = 已验证的高成功率镜头构图
```

当前 `types.ts` 中 `Character.variations` 已有变体概念，可向上抽象为完整的**资产卡体系**。

### 3.2 借鉴 Wind Comic 的 Character DNA

替代纯文本 role reference（当前方案）：用 VLM 从角色定妆照中提取结构化特征向量 → 注入每帧 prompt → 生成后做相似度校验。

**代码层面**: 在 `visualService.ts` 的 `generateCharacterVisualPrompt` 返回中增加 `characterDna` 字段，在 `generateImage` 时作为额外约束传入。

### 3.3 借鉴 Catimind 的低精度→高精度策略

当前项目所有生成都是全精度（标准/4K 是画质参数，不是预览模式）。

**新增功能**: 在 VideoGenerator 中增加"预览模式"切换
- 预览模式：480p/24fps/快速模型 → 确认后批量精修
- 全精度模式：1080p/30fps/高质量模型

### 3.4 借鉴 Wind Comic 的校验+自动重试

当前项目生成后没有任何自动校验。用户只能靠肉眼判断。

**新增功能**: 
- 关键帧生成后：VLM 校验角色相似度 + 风格一致性
- 低分自动重试（带增强约束）
- 校验结果在 UI 上可视化展示

### 3.5 借鉴 Micro Drama Toolkit 的 Series Bible

当前项目有 `ProjectState` 作为项目级数据，但没有**统一的"剧本圣经"**供所有模块引用。

```
Series Bible = {
  角色关系图,       // 不是只有角色列表，还有角色之间的关系
  世界观规则,       // 时间/空间/物理规则一致性
  情感曲线,         // 全剧情绪波动图
  道具连续性清单,    // 哪些道具持续出现
}
```

当前 `rawScript` 存了原始剧本，但分镜生成后就不再引用。Series Bible 为所有后续阶段提供**单一真相源**。

## 五、结论

行业共识高度一致：

1. **角色一致性是"生死线"** — 所有工具最大的投入都在解决这个。Wind Comic 的 Character DNA + Vision Audit 是目前公开的最完整方案（商业产品的内部方案可能更强但不开源）
2. **资产复用是降本核心** — "建一次用一百次"是 Catimind 的核心价值。当前项目有资产概念但没有复用体系
3. **分两次生成能省钱出效果** — 低精度预览→高精度精修，这不仅是成本策略，也是质量策略（先确认节奏再投算力）
4. **AI 校验不能省** — 生成后自动校验可以拦截 30-50% 的低质量输出，节省用户反复试错的时间
5. **Pipeline 设计已高度标准化** — 所有工具的 pipeline 结构都类似：剧本→角色→分镜→生成→合成→导出。差异在于每个阶段的深度和 AI 介入方式

**当前项目在 pipeline 完整性上不输竞品，但在角色一致性、资产复用、AI 校验、预览机制四个维度存在明显差距。**
