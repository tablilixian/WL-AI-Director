## 优先级定义

| 等级 | 含义 | 预期耗时 |
|------|------|---------|
| 🔴 P0 | 必须优先修复，阻塞后续功能 | 2-4 小时 |
| 🟡 P1 | 建议近期完成，提升可用性 | 2-4 小时 |
| 🟢 P2 | 可延后，完善体验 | 1-3 小时 |
| ⚪ P3 | 远景规划，需要设计后再实施 | 4-8 小时 |

## 阶段 A：AI 提示词工程

| 优先级 | 编号 | 问题 | 类型 | 平台级描述 | 建议方案 |
|--------|------|------|------|-----------|---------|
| 🟡 P1 | A01 | LLM 输出缺乏领域知识注入机制 | FEATURE | 用户无法向 AI 注入项目专属知识（历史/文化/风格等），AI 只依赖训练数据中的通用印象 | `ProjectState` 增加 `eraContext` / `knowledgeBase` 字段，`buildKeyframePrompt` 和 `buildVideoPrompt` 中注入该上下文 |
| 🟢 P2 | A02 | 中文输出丢失专业英文术语 | BUG | 提示词指定中文输出时 AI 自动翻译/丢弃英文视觉术语（如 Rembrandt lighting） | 在 prompt 模板中显式声明"保留以下英文术语不翻译"段落，将常用术语表拼入 system prompt |
| 🟡 P1 | A04 | 场景提示词硬编码风格 | BUG | `generateSceneVisualPrompt` 中 `getStylePrompt('anime')` 写死了 anime，未使用用户选择的 visualStyle | 将 `getStylePrompt('anime')` 改为 `getStylePrompt(project.visualStyle)` 或从参数传入 |
| 🟢 P2 | A05 | 质量标签去重只匹配英文 | BUG | `enhanceWithQualityTags` 用正则只匹配英文去重，中文等效词（"电影级画质"/"8K"）不触发 | 扩展正则模式，加入中英文常见质量标签映射表 |

## 阶段 B：剧本→分镜映射（叙事逻辑）

| 优先级 | 编号 | 问题 | 类型 | 平台级描述 | 建议方案 |
|--------|------|------|------|-----------|---------|
| 🔴 P0 | B03 | 关键帧视觉提示词重复率过高 | BUG | 通用风格描述的机械拼接导致每帧提示词几乎相同，AI 缺乏"每帧必须唯一"的约束 | `buildKeyframePrompt` 中注入帧类型差异化约束（如 start 帧侧重场景建立，end 帧侧重动作收束），参考 `cameraChoreography.startShotSize` / `endShotSize` 生成差异化描述 |
| 🔴 P0 | B04 | 角色分配忽略"在场约束" | BUG | 分镜生成把全部角色分配给所有镜头，未检查角色在该时刻是否物理在场 | 分镜生成 prompt 中增加"角色在场时间线"约束，解析 rawScript 中的角色出场/退场标记 |
| 🟡 P1 | B07 | 运镜类型池太小 | FEATURE | Dolly/Tracking 占 60%，Crane/Steadicam/POV/Handheld 从未出现 | 建立按情绪分类的运镜库（`cameraMovementGuides.ts` 已有框架），在 `buildVideoPrompt` 中按 shot 情绪权重采样 |
| 🟡 P1 | B05 | 镜头数量按段落均分 | FEATURE | 情绪高潮段与平淡段获得相同镜头数 | 引入情绪权重算法，高潮段分配更多镜头；`shotGenerationModel` prompt 中注入"节奏权重"参数 |
| 🟢 P2 | B08 | Keyframe 类型只支持 start/end | FEATURE | 动作跨时长时只有首尾帧无法控制中间过程 | 新增 `type: 'mid'` 支持，`Shot` 增加 `midKeyframes` 或扩展 `keyframes` 允许同 type 多帧；`TimedKeyframe` 已有时间位置信息可复用 |
| 🟢 P2 | B09 | AI 未提取剧本中的视觉细节 | FEATURE | 手部动作、道具特写、微表情等"名场面"细节未被分配到对应镜头 | 剧本解析步骤增加"视觉细节提取"子阶段，信息存入 shot 的新字段（如 `visualDetails`） |

## 阶段 C：导演工作台 UI（交互与编辑能力）

| 优先级 | 编号 | 问题 | 类型 | 平台级描述 | 建议方案 |
|--------|------|------|------|-----------|---------|
| 🟡 P1 | C06 | `buildKeyframePrompt` 将合成 prompt 写回用户 visualPrompt | BUG | 合成 prompt 的逻辑存在副作用，覆盖了用户手工编辑的关键帧描述 | 与 A07 不同：C06 是生成时的数据流错误，A07 是锁定标志。修复 `handleOptimizeKeyframeWithAI` 等函数，确保合成结果只用于生成调用，不写回 `visualPrompt` 字段 |
| 🟢 P2 | C02 | 角色多选 UI 仅显示 ID 不显示名称 | UX | 用户无法将角色 ID 与人名对应，编辑效率低 | `ShotWorkbench.tsx` 角色下拉列表显示 `character.name` 而非 `character.id` |
| 🟢 P2 | C03 | 某些 UI 布局下只有 start 帧编辑器 | UX | 存在 UI 变体仅展示一个关键帧，用户以为只有一帧 | 检查 `ShotWorkbench.tsx` 和 `KeyframeEditor.tsx` 的条件渲染逻辑，确保 end 帧始终可见 |
| 🟢 P2 | C04 | 修改结果异常无法回溯原因 | UX | 缺少"修改了什么→影响了什么"的因果关系提示 | 生成操作前记录关键状态快照，出错时对比显示变更差异（字段级 diff） |
| ⚪ P3 | C05 | 无 undo/redo 机制 | FEATURE | `updateShot` 直接覆盖，所有操作不可逆 | 需要 Zustand middleware（如 `temporal`）或手动维护操作历史栈，涉及 store 架构变更 |

## 阶段 E：数据持久化与跨会话恢复

| 优先级 | 编号 | 问题 | 类型 | 平台级描述 | 建议方案 |
|--------|------|------|------|-----------|---------|
| 🟡 P1 | E02 | UI 组件卸载后高级参数丢失 | BUG | Tab 切换或组件重渲染后用户已调整的高级参数未持久化 | 当前已在 `handleAdvancedGenerateVideo` 生成时写回 `shot.interval`，但用户调整后未生成就切换 Tab 会丢失。增加 `useEffect` 在组件卸载前保存到 `shot.interval` |
| 🟢 P2 | E03 | Base64 视频嵌入 JSON 导致导出体积过大 | PERF | 已有问题，非本次引入 | 优先使用 `local:` 引用模式，导出时只包含引用路径；大视频单独存储 |
| ⚪ P3 | E04 | 数据导入只有 veo-r2v→veo 一种迁移 | FEATURE | 数据版本升级时只能单项迁移 | 建立通用迁移框架，`version` 字段 + 版本号排序迁移函数链 |

## 推荐执行顺序

```
第一优先级（P0 — 直接影响生成质量）
  ├── B03：关键帧提示词去重
  ├── B04：角色在场约束
  └── 完成后即有明显效果提升

第二优先级（P1 — 提升可用性和正确性）
  ├── A01：领域知识注入（与 B 系列叙事修复搭配）
  ├── A04：场景提示词风格参数化（1 行改动）
  ├── B05：情绪权重分镜
  ├── B07：运镜类型池扩展
  ├── C06：buildKeyframePrompt 副作用
  ├── E02：Tab 切换丢状态（与 D 系列用户体验相关）
  └── 完成后核心编辑体验趋于完整

第三优先级（P2 — 完善体验）
  ├── A02：中英术语混写
  ├── A05：质量标签中文去重
  ├── B08：中间帧类型支持
  ├── B09：视觉细节提取
  ├── C02：角色多选显示名称
  ├── C03：end 帧编辑器可见性
  ├── C04：修改因果提示
  ├── E03：导出体积优化
  └── 锦上添花，按需选取

第四优先级（P3 — 架构级）
  ├── C05：undo/redo
  ├── E04：通用数据迁移框架
  └── 需要设计评审后再实施
```
