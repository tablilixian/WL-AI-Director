## OP-001: 角色视觉提示词缺乏历史细节锚点

- **问题等级**: 🔴 严重
- **涉及文件**: `services/ai/visualService.ts:424-518` (`generateCharacterVisualPrompt`)
- **涉及文件**: `services/ai/visualService.ts:625-738` (`generateVisualPrompt`)

### 问题描述

项目自动生成的视觉提示词缺少对角色服装颜色、材质、年代特征的精确描述。例如李云龙被生成"深棕色军装、手持大刀"而非"灰蓝色八路军军装、腰别驳壳枪"。

AI 模型缺乏历史知识，对"八路军军装"的理解停留在脸谱化层面。

### 根因分析

系统 prompt 中未要求 AI 关注**历史准确性 (historical accuracy)** 和 **服装材质/颜色/年代特征**。AI 倾向使用泛化的"军装、大刀"等标签，因为这些词在训练数据中出现频率更高。

### 优化方案

在 `generateCharacterVisualPrompt` 的 system prompt 中增加历史约束段落。修改位置: `visualService.ts:480-506`

```diff
 CRITICAL REQUIREMENTS:
 1. Describe the character's appearance in DETAIL:
    - Facial features (eyes, nose, mouth, eyebrows, expression)
    - Hair (length, color, texture, style, accessories)
    - Body type and proportions
    - Clothing/outfit (style, color, materials, accessories)
+   - 【历史准确性】服装颜色、材质、款式必须准确对应历史时期
+   - 【时代特征】确保武器、配饰、发型符合该年代特征
+   - 【实地感】服装应有旧损、尘土、汗渍等真实使用痕迹
+   - 绝对避免：现代审美、光鲜整洁、健美模特化的描述
    - 【MANDATORY】Include signature pose...
```

## OP-002: 缺少专业摄影风格描述锚点

- **问题等级**: 🔴 严重
- **涉及文件**: `services/ai/promptConstants.ts:10-17` (`VISUAL_STYLE_PROMPTS`)
- **涉及文件**: `services/ai/visualService.ts:424-518`

### 问题描述

项目生成的提示词只写"光影对比强烈"这种泛化描述。我给的提示词中 `cinematic Rembrandt lighting, chiaroscuro, shot on vintage anamorphic lens, film grain, war film aesthetics` 能准确导向战争电影视觉效果。

AI 输出语言为中文时，丢失了英文电影摄影术语的表现力。

### 根因分析

1. `generateCharacterVisualPrompt` 指定 `language: '中文'` 输出
2. 即使 `artDirection.consistencyAnchors` 包含英文风格描述，AI 在产出中文提示词时会"翻译"掉这些术语
3. 中文 LLM 对 `chiaroscuro`、`Rembrandt lighting`、`anamorphic lens` 等术语的理解深度不如英文 LLM

### 优化方案

**方案 A（推荐）**：在视觉提示词生成中，保留英文风格锚点代码块，不翻译。

在 `visualService.ts:503` 附近，修改输出格式要求：

```diff
 4. Language:
-   - Write the prompt in ${language}
-   - Use natural, flowing language
+   - Write the prompt in ${language}
+   - BUT must include the following ENGLISH style anchor terms verbatim:
+     - "cinematic lighting, film grain texture, shallow depth of field"
+     - "historical authenticity, natural skin texture, worn and battle-tested"
+     - "photorealistic, war film aesthetics, dramatic chiaroscuro"
+   - Use natural, flowing language
```

**方案 B**：修改 `promptConstants.ts` 中 `VISUAL_STYLE_PROMPTS['live-action']` 增加更多专业术语。

当前值:
```
photorealistic, cinematic film quality, real human actors, professional cinematography,
natural lighting, 8K resolution, shallow depth of field, film grain texture,
color graded, anamorphic lens flare, three-point lighting setup
```

建议增加:
```
+ Rembrandt lighting, chiaroscuro, vintage anamorphic lens, war film aesthetics,
+ historical authenticity, natural skin texture with pores and imperfections,
+ dramatic shadows, desaturated color palette
```

## OP-003: Negative Prompt 未被有效使用

- **问题等级**: 🔴 严重
- **涉及文件**: `services/ai/visualService.ts:625-738` (`generateVisualPrompt`)
- **涉及文件**: `services/ai/promptConstants.ts:38-46` (`NEGATIVE_PROMPTS`)

### 问题描述

项目中虽然定义了 `NEGATIVE_PROMPTS`，但在 `generateCharacterVisualPrompt`（行424-518）中**根本没有返回 negative prompt**——该函数只返回 `visualPrompt: string`，没有 negative prompt 字段。

只有在 `generateVisualPrompt`（行625-738）和 `generateAllCharacterPrompts`（行1298-1407）中才有 negative prompt 输出。这意味着如果在 StageAssets 中逐个生成角色提示词（调用 `generateCharacterVisualPrompt`），**负提示词完全缺失**。

缺少负提示词导致 AI 默认生成"光鲜、磨皮、微笑"的图。

### 根因分析

`generateCharacterVisualPrompt` 的返回值类型是 `Promise<string>`，只返回正提示词。而 `generateVisualPrompt` 返回 `Promise<{ visualPrompt: string; negativePrompt: string }>`。两个函数有重复逻辑但签名不一致。

### 优化方案

**步骤 1**：修改 `generateCharacterVisualPrompt` 返回类型，增加 negativePrompt：

```diff
- export const generateCharacterVisualPrompt = async (...): Promise<string> => {
+ export const generateCharacterVisualPrompt = async (...): Promise<{ visualPrompt: string; negativePrompt: string }> => {
```

**步骤 2**：在输出格式要求中添加 negative prompt：

```diff
- Output ONLY the visual prompt (no explanations, no JSON format). Length: 200-400 words.
+ Output ONLY valid JSON with this exact structure:
+ {
+   "visualPrompt": "detailed visual prompt (200-400 words)",
+   "negativePrompt": "negative prompt describing what to avoid - include: modern fashion, clean appearance, smiling, cartoon, anime, illustration, overexposed, bright colors, glamour, makeup, fantasy elements"
+ }
```

**步骤 3**：在 `promptConstants.ts` 的 `NEGATIVE_PROMPTS['live-action']` 中增加针对性排除项：

当前:
```
cartoon, anime, illustration, painting, drawing, 3d render, cgi, low quality,
blurry, grainy, watermark, text, logo, signature, distorted face, bad anatomy,
extra limbs, mutated hands, deformed, ugly, disfigured, poorly drawn, amateur
```

建议增加:
```
+ modern fashion, clean clothes, smiling, bright colors, glamour, makeup,
+ smooth skin, airbrushed, perfect teeth, fitness model physique, staged,
+ overly dramatic, fantasy, sci-fi elements
```

## OP-004: 场景视觉提示词与角色风格不耦合

- **问题等级**: 🟡 中等
- **涉及文件**: `services/ai/visualService.ts:524-615` (`generateSceneVisualPrompt`)

### 问题描述

`generateSceneVisualPrompt` 硬编码了 `const stylePrompt = getStylePrompt('anime')`（行534），无论用户选择什么视觉风格，场景提示词都按 anime 风格生成。这会导致 live-action 项目中的场景描述偏向动漫化。

### 根因分析

代码硬编码了 `'anime'`，应该是使用传入的 `visualStyle` 参数。

### 优化方案

```diff
- const stylePrompt = getStylePrompt('anime');
+ const stylePrompt = getStylePrompt(visualStyle);
```

同时修改 system prompt 中的引用：

```diff
- You are a world-class visual prompt engineer for anime productions.
+ You are a world-class visual prompt engineer for ${visualStyle} productions.
```

## OP-005: 视觉风格锚点未正确传递到最终提示词

- **问题等级**: 🟡 中等
- **涉及文件**: `services/ai/promptConstants.ts:66-68` (`DEFAULT_QUALITY_TAGS`)
- **涉及文件**: `services/ai/promptConstants.ts:73-79` (`enhanceWithQualityTags`)

### 问题描述

`enhanceWithQualityTags` 会检查 prompt 中是否包含 `cinematic|8K|photorealistic|highly detailed|professional|sharp focus|film grain` 这些词，如果存在则不做追加。但 AI 生成的提示词中可能包含这些词的通顺中文变体（如"电影级画质"、"8K分辨率"），此时正则匹配失败，会重复追加英文标签，导致 prompt 中出现"cinematic, 8K resolution"的英文混搭中文的情况。

### 根因分析

正则匹配只查英文关键词，没查中文对应词。而且 `DEFAULT_QUALITY_TAGS` 是纯英文，统一追加可能导致中英混杂。

### 优化方案

**方案 A**：扩大正则匹配，同时识别中英文：

```diff
- const hasQualityTerms = /cinematic|8K|photorealistic|highly detailed|professional|sharp focus|film grain/i.test(prompt);
+ const hasQualityTerms = /cinematic|8K|photorealistic|highly detailed|professional|sharp focus|film grain|电影级|8K|写实|专业|锐|胶片/i.test(prompt);
```

**方案 B**：在中文 prompt 中使用中文质量标签：

```diff
- export const DEFAULT_QUALITY_TAGS = 'cinematic, highly detailed, 8K resolution, professional lighting, sharp focus, film grain texture';
+ export const DEFAULT_QUALITY_TAGS = 'cinematic, highly detailed, 8K resolution, professional lighting, sharp focus, film grain texture';
+ export const DEFAULT_QUALITY_TAGS_CN = '电影级画质，超高细节，8K分辨率，专业布光，焦点清晰，胶片颗粒质感';
```

并在中文输出流中追加中文标签。

## OP-006: 角色服装/道具随场景变化的衣橱系统未与剧本联动

- **问题等级**: 🟡 中等
- **涉及文件**: `services/ai/scriptService.ts`（剧本解析）

### 问题描述

剧本中秀芹有"日常装"和"被俘破损装"两种状态，李云龙有"指挥装"和"战斗装"。但项目中 `Character.variations` 需要手动创建，AI 不会自动从剧本中对白/场景描述中推断出角色在不同场次中的服装状态变化。

### 根因分析

剧本解析阶段只提取了角色的基本属性（姓名、性别、年龄、性格），没有分析每个场景中角色应处的状态（着装、受伤程度等）。

### 优化方案

在剧本解析 prompt 中增加：

```
【角色状态推断】对于每个角色，分析他们在不同场景中的状态变化：
- 服装状态（整洁/战斗破损/特殊服装）
- 情绪状态（愤怒/悲伤/冷静）
- 物理状态（健康/受伤/疲惫）

输出格式示例：
李云龙:
  - 场景2: 基准指挥装, 愤怒
  - 场景4: 战斗装(尘土+汗渍), 决绝
  - 场景5: 战后悲怆装, 悲痛
```

根据解析结果自动创建 `CharacterVariation`。

## OP-007: 提示词生成缺乏"负面约束"的显式传递

- **问题等级**: 🟢 建议
- **涉及文件**: `services/ai/visualService.ts:140-175` (`generateImage`)

### 问题描述

`generateImage` 函数组装 finalPrompt 时，只处理了正提示词 (prompt) 和参考图逻辑，**没有任何 negative prompt 的传递通道**。即使 `generateVisualPrompt` 返回了 negativePrompt，最终调用 `callImageApi` 时也没有传过去。

### 根因分析

`callImageApi` 的接口定义中可能缺少 negative prompt 参数。需要检查 `imageAdapter.ts` 中的接口定义。

### 优化方案

**步骤 1**：检查 `imageAdapter.ts` 中的 `callImageApi` 参数是否支持 negative prompt。

**步骤 2**：将 negativePrompt 从 `generateVisualPrompt` → `generateImage` → `callImageApi` 逐层传递。

**步骤 3**：如果图像 API 不支持 negative prompt，至少将其作为正提示词的一部分附加（"请避免...不要..."），或使用风格约束段落。

## OP-008: 角色 visualPrompt 被重复使用但缺乏版本管理

- **问题等级**: 🟢 建议
- **涉及文件**: `services/ai/visualService.ts`

### 问题描述

用户手动在 UI 中编辑角色的 `visualPrompt` 并手动生成效果更好的图后，下次 AI 重新生成时会覆盖掉用户的编辑。没有"锁定/手动模式"的概念。

### 优化方案

在 `Character` 类型中增加一个标记字段：

```typescript
interface Character {
  // ... 现有字段
  visualPromptSource: 'auto' | 'manual'  // 新增
  // 当为 'manual' 时，跳过 AI 重新生成
}
```

在 `generateCharacterVisualPrompt` 中判断：

```typescript
if (character.visualPromptSource === 'manual' && character.visualPrompt) {
  return { visualPrompt: character.visualPrompt, negativePrompt: character.negativePrompt || '' };
}
// 否则 AI 生成
```

## OP-009: 镜头与剧本场景严重错位

- **问题等级**: 🔴 严重
- **涉及文件**: `services/ai/scriptService.ts`（剧本→分镜解析逻辑）

### 问题描述

剧本有5个逻辑场景（场次1-5），但分镜系统生成了9个场景ID（1-9）和27个镜头。镜头分配与剧本完全不一致：

| 剧本场次 | 实际内容 | 分镜 sceneId | 分镜实际描述 | 问题 |
|---------|---------|-------------|-------------|------|
| 场景1: 赵家峪惨案 | 日军突袭→秀芹被抓→李云龙回村 | 1 | "集结部队攻打平安县城" | **错位**：惨案还没发生就先集结了 |
| 场景2: 集结 | 指挥部决策 | 2 | "秀芹被日军押送" | **错位**：还在集结阶段就秀芹被抓了 |
| 场景3: 兵临城下 | 围城、对峙 | 5 | "部队集结" | **错位**：场景3变回集结 |
| 场景4: 血战 | 攻城→意大利炮→开炮 | 8 | "李云龙下令开炮" | **包含在镜头24，但无台词** |
| 场景5: 尾声 | 战后废墟 | 9 | "李云龙悲痛" | 基本正确 |

### 根因分析

AI 在剧本→分镜解析时，没有严格按照剧本的**场景划分**来映射。而是按照故事段落（storyParagraphs）的线性顺序生成9个场景，但 storyParagraphs 本身的对齐就不精确（9段对应5个实景）。分镜生成的 prompt 也没有要求"镜头所属场景必须与剧本场景一致"。

### 优化方案

在分镜生成的 prompt 中增加场景对齐约束：

```
【场景绑定规则】
- 每个镜头必须严格绑定到一个剧本场景
- 镜头内容不可超出该场景的时间/地点/人物范围
- 场景编号与剧本编号一一对应（不以 storyParagraph 数量为准）
- 输出格式：每个镜头必须包含 sceneRefId 和 sceneName
```

## OP-010: 所有镜头未携带剧本台词

- **问题等级**: 🔴 严重
- **涉及文件**: `services/ai/scriptService.ts`（分镜生成）

### 问题描述

27个镜头中，只有 shot-6、shot-10、shot-11、shot-12 有 dialogue 字段，其余23个镜头 dialogue 为空字符串。但剧本中有大量经典台词：

| 剧本台词 | 所在镜头 | 镜头是否有台词 |
|---------|---------|-------------|
| "山本！老子跟你没完！" | 应在 scene 1 | ❌ 空 |
| "老赵，我老婆被鬼子抓了" | 应在 scene 2 | ❌ 空 |
| "老子管他什么县城！" | 应在 scene 2 | ❌ 空 |
| "二营长……开炮。" | 应在 scene 4 | ❌ 空（"开炮"被错误分配到 shot-22/24 但无台词） |
| "进攻——！" | 应在 scene 4 | ❌ 空 |
| "李云龙！开炮！" | 应在 scene 4 | ❌ 空 |
| "秀芹……我对不住你" | 应在 scene 5 | ❌ 空 |

### 根因分析

分镜生成过程中，AI 从 storyParagraphs 提取了场景概括性文本（如"独立团团长李云龙为救被日军抓走的妻子，率部攻打平安县城"），但**没有从 rawScript 中提取每个场景的具体台词**。系统 prompt 可能只要求"概括镜头内容"，没有要求"提取该镜头涉及的对白"。

### 优化方案

在分镜生成 prompt 中增加台词提取要求：

```
【对白提取规则】
- 从原始剧本(rawScript)中定位每个镜头对应的文本段落
- 提取该段落中所有角色的对白（格式：角色名: "对白内容"）
- 如果没有对白，标注"无对白"
- 将提取的对白填入该镜头的 dialogue 字段
- 确保经典台词不被遗漏，尤其高潮段落
```

## OP-011: 关键帧视觉提示词大量雷同

- **问题等级**: 🔴 严重
- **涉及文件**: `services/ai/shotService.ts`（镜头关键帧生成）

### 问题描述

27个镜头的54个关键帧中，"冷色调中带有微妙的红色调，光影对比强烈，营造出战争的压抑氛围" 这类描述出现了 **40+ 次**，几乎每个镜头都一模一样。start 和 end 关键帧的区别只是"镜头缓慢推进/拉远"等通用描述。

对比我给的镜头的专业描述（每个镜头有独特的构图、光线、情绪），项目生成的提示词几乎**没有区分度**。

### 根因分析

1. `shotService.ts` 生成关键帧 prompt 时，把 `artDirection.consistencyAnchors` 等通用风格描述机械拼接到每个镜头
2. AI 缺乏对单个镜头"独特性"的要求，倾向于复用最安全的通用描述
3. start/end 帧的区别只要求了运镜变化，没有要求**画面内容的变化**

### 优化方案

在 shotService 的关键帧 prompt 中增加差异化约束：

```diff
【关键帧描述要求】
- 每个关键帧必须具有唯一性描述，不可与其他镜头雷同
- start帧：描述具体的画面构图、人物位置、表情、动作
- end帧：描述画面变化后的状态（人物移动了？表情变了？环境变了？）
- 每帧必须回答：这个镜头在这个时刻，观众应该看到什么具体画面？
- ❌ 禁止使用通用套话："冷色调中带有微妙的红色调，光影对比强烈"
- ✅ 应该写："李云龙右手按在炮绳上，青筋暴起，背景是炮口对准的城楼，硝烟从炮管旁飘过"
```

## OP-012: 角色分配与剧本不符

- **问题等级**: 🔴 严重
- **涉及文件**: `services/ai/shotService.ts`（镜头角色分配）

### 问题描述

多个镜头的 characters 数组包含所有角色，与实际剧情不符：

| 镜头 | sceneId | 剧情实际应有角色 | JSON 中角色分配 |
|------|---------|----------------|----------------|
| shot-1 | 1 (赵家峪惨案) | 李云龙、秀芹、日军 | 全部6个角色 |
| shot-2 | 1 (赵家峪惨案) | 李云龙 | 全部6个角色 |
| shot-3 | 1 (赵家峪惨案) | 李云龙、八路军战士 | 全部6个角色 |
| shot-14 | 5 (兵临城下) | 秀芹此时应在城楼被绑 | "杨秀芹在队伍中快速移动，准备战斗" |
| shot-17 | 6 (攻防阵地) | 冲锋的八路军战士 | 角色"2"（杨秀芹）❌ |

### 根因分析

系统在分配角色到镜头时，没有考虑：
1. 该角色在该场景中是否**物理在场**
2. 该角色在该时点的**状态**（秀芹已被抓，不可能在攻城队伍中）
3. 剧本中未出场的角色不应出现在镜头中

### 优化方案

在分镜生成 prompt 中加入角色在场约束：

```
【角色在场约束】
- 分析剧本中每个场景/时刻，哪些角色物理在场
- 不在该场景的角色不得分配到镜头
- 被俘/死亡/远方的角色应标记为不在场
- 每个镜头只列出确实出现在画面中的角色
- 角色状态应与剧本时间线一致（例如秀芹被抓后不应出现在城外队伍中）
```

## OP-013: 高潮段落镜头密度不足

- **问题等级**: 🟡 中等
- **涉及文件**: `services/ai/shotService.ts`（分镜节奏控制）

### 问题描述

27个镜头在5个场景中的分布：

| 场景 | 剧本情绪强度 | 镜头数 | 占比 |
|------|------------|--------|------|
| 场景1: 赵家峪惨案 | ⭐⭐⭐ | 3个 (shot-1~3) | 11% |
| 场景2: 集结 | ⭐⭐⭐ | 3个 (shot-4~6) | 11% |
| 场景3: 兵临城下 | ⭐⭐⭐ | 3个 (shot-7~9) | 11% |
| 场景4: 血战（高潮） | ⭐⭐⭐⭐⭐ | 5个 (shot-10~14) | 19% |
| 场景5: 攻城战斗 | ⭐⭐⭐⭐ | 3个 (shot-15~18) | 15% |
| 场景6: 意大利炮 | ⭐⭐⭐⭐⭐ | 3个 (shot-19~21) | 11% |
| 场景7: 城楼对峙 | ⭐⭐⭐⭐⭐ | 3个 (shot-22~24) | 11% |
| 场景8: 开炮+牺牲 | ⭐⭐⭐⭐⭐ | 3个 (shot-25~27) | 11% |

整个故事最高潮的段落（"二营长开炮"→秀芹牺牲→李云龙痛哭）只有3个镜头，而平淡的集结段落也有3个镜头。**高潮部分镜头密度应该更高**，通过多角度、多景别来强化情绪冲击。

### 根因分析

分镜生成是按 storyParagraphs 数量线性分配镜头数的，而不是按照**情绪曲线**动态分配。每个段落分配约3个镜头，不考虑该段落在整体叙事中的权重。

### 优化方案

在分镜生成逻辑中加入情绪权重分配：

```
【镜头密度规则】
- 分析每个场景的情绪强度（1-5星）
- 镜头数 = 基准数(3) × 情绪权重系数
  - ⭐⭐⭐⭐⭐ = 6-8个镜头（高潮段多角度渲染）
  - ⭐⭐⭐⭐ = 4-5个镜头
  - ⭐⭐⭐ = 3个镜头（基准）
  - ⭐⭐ = 2个镜头
- 高潮段必须包含：广角定场 + 中景 + 特写(表情) + 特写(动作) + 慢动作
```

## OP-014: 镜头中未使用已生成的角色/场景参考图

- **问题等级**: 🟡 中等
- **涉及文件**: `services/ai/shotService.ts`（关键帧生成）

### 问题描述

在 JSON 中可以看到，`scene` 和 `character` 都有 `imageUrl` 字段指向已生成的参考图（如 `local:img_1783912761179_1n17o9d`）。但在 `shot.keyframes[].visualPrompt` 中，**没有任何提示词引用这些参考图**。

这意味着生成关键帧图像时，AI 没有收到"角色的长相应该是这张图的样子"的约束，导致同一角色在不同镜头中可能长不一样。

### 根因分析

`keyframes[].visualPrompt` 只存储了文本描述，没有存储对应的 reference image URL。在 `generateImage` 调用中，虽然有 `referenceImages` 参数，但 shotService 没有把角色的 `imageUrl` 传给它。

### 优化方案

在 Shot 的关键帧数据结构中增加 reference 字段：

```typescript
interface Keyframe {
  id: string
  type: 'start' | 'end'
  visualPrompt: string
  imageUrl?: string
  status: 'pending' | 'generating' | 'completed' | 'failed'
+ referenceCharacterIds?: string[]   // 需要参考哪些角色的定妆照
+ referenceSceneId?: string           // 需要参考哪个场景图
}
```

生成图像时：
```
1. 根据 referenceCharacterIds 查找对应角色的 imageUrl
2. 根据 referenceSceneId 查找对应场景的 imageUrl
3. 将这些 referenceImages 传入 generateImage
4. 在 visualPrompt 末尾追加："角色面部特征请严格参考参考图"
```

## OP-015: 运镜类型单一且重复

- **问题等级**: 🟡 中等
- **涉及文件**: `services/ai/shotService.ts`（运镜逻辑）

### 问题描述

27个镜头的运镜分布：

| 运镜类型 | 出现次数 |
|---------|---------|
| Dolly Shot (推拉) | 9次 |
| Tracking Shot (跟拍) | 7次 |
| Wide Shot / Static Shot | 4次 |
| Zoom In Shot (变焦推) | 3次 |
| Pan Right (右摇) | 2次 |
| Tilt Up (仰拍) | 1次 |
| Over the Shoulder (过肩) | 1次 |

严重缺乏：
- **Crane Shot / Boom Shot**（升降镜头）: 0次 — 适合展现战场全景
- **Steadicam**（稳定跟拍）: 0次 — 适合冲锋镜头
- **Handheld**（手持晃动）: 0次 — 适合紧张/混乱场面
- **POV**（主观视角）: 0次 — 适合"从李云龙视角看到秀芹被绑"
- **Aerial / Bird's-eye**（航拍/鸟瞰）: 0次 — 适合展现包围态势

### 根因分析

shotService 的运镜池太小，AI 倾向于在有限的运镜类型中循环使用。缺乏一个"运镜类型库"供 AI 根据场景情绪选择。

### 优化方案

建立运镜类型库，按情绪分类：

```typescript
const CAMERA_MOVEMENT_LIBRARY = {
  epic: ['Crane Shot', 'Aerial View', 'Wide Tracking', 'Steadicam Follow'],
  tense: ['Handheld Shake', 'Quick Zoom', 'Snap Pan', 'POV'],
  dramatic: ['Slow Dolly In', 'Crane Down', 'Tilt Up Reveal', 'Dutch Angle'],
  action: ['Tracking Follow', 'Handheld Run', 'Whip Pan', 'Crash Zoom'],
  emotional: ['Slow Push In', 'Float Cam', 'Circle Dolly', 'Rack Focus'],
}
```

在分镜生成 prompt 中：

```
【运镜选择规则】
- 根据该镜头的情绪选择运镜类型：
  - 宏大场面（集结、全景）→ epic 类
  - 紧张对峙 → tense 类
  - 情感高潮（开炮、牺牲）→ dramatic + emotional 类
  - 战斗动作 → action 类
- 同一场景内连续镜头避免使用相同运镜
- 避免连续3个以上 Dolly Shot
```

## OP-016: 关键帧只有首尾帧，缺少多帧分解

- **问题等级**: 🟢 建议
- **涉及文件**: `types/editor.ts`（Shot 类型定义）

### 问题描述

当前每个镜头只有 start 和 end 两个关键帧。对于复杂动作场景（如炮弹飞行的全过程、李云龙从痛苦到决绝的表情变化），仅靠首尾帧无法精确控制中间过程。

例如 shot-24（开炮镜头）：
- start: "李云龙下令开炮"
- end: "炮弹升空"

缺少：
- 炮弹飞行的过程
- 秀芹看到炮弹的表情变化
- 炮弹击中城楼的瞬间

### 根因分析

`Shot.keyframes` 只定义了 `type: 'start' | 'end'`，不支持中间帧。视频生成模型虽然可以自动插值，但中间过程不可控。

### 优化方案

扩展 Keyframe 类型：

```typescript
interface Keyframe {
  id: string
- type: 'start' | 'end'
+ type: 'start' | 'mid' | 'end'    // 增加中间帧
+ timingPercent?: number            // 该关键帧在镜头中的时间位置（0~100）
  visualPrompt: string
  imageUrl?: string
  status: 'pending' | 'generating' | 'completed' | 'failed'
}
```

对于关键镜头（如炮弹发射、开炮决定），自动生成3-5个关键帧，确保中间过渡可控。

### 问题描述

剧本中的以下关键细节在分镜中完全缺失：

| 剧本细节 | 重要性 | 镜头覆盖 |

```
  2. 物品特写（望远镜、衣角碎片、击发绳）
  3. 人物微表情（眼泪滑落、嘴角颤抖、微笑）
  4. 环境细节（火光映照侧脸、硝烟中的残阳）
- 将这些细节分配到最近的镜头中作为特写或中景
- 每个场景至少包含 1-2 个细节特写镜头
- 经典名场面必须保留（如拉击发绳、秀芹微笑）
```
