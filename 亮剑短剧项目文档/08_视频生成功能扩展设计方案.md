## 发现 1：数据割裂 — interval 和 videoSettings 各管一摊

### 问题
当前方案把**生成参数**（mode, fps, resolution）放到 `shot.videoSettings`，但**生成结果**（videoUrl, status）仍在 `shot.interval` 里。两份数据在 JSON 层面是独立的：

```json
{
  "shot": {
    "interval": {
      "startKeyframeId": "kf_001",
      "endKeyframeId": "kf_005",    ← 只有首尾
      "duration": 15,
      "videoUrl": "data:video...",
      "status": "completed"
    },
    "videoSettings": {
      "mode": "mkr",
      "mkr": {
        "keyframes": [
          {"keyframeId": "kf_001", "positionPercent": 0},
          {"keyframeId": "kf_002", "positionPercent": 25},  ← 中间帧不在 interval 中体现
          {"keyframeId": "kf_003", "positionPercent": 50},
          {"keyframeId": "kf_005", "positionPercent": 100}
        ]
      }
    }
  }
}
```

### 后果
- 重写 `handleGenerateVideo` 逻辑时，函数的签名只有 `(shot, aspectRatio, duration, modelId)`，不知道要用什么 mode
- 第一次生成后用 MKR，第二次点"重新生成"时，系统看到 `interval` 只有首尾帧，就用默认模式重新生成 — 用户发现效果变了
- `motionStrength` 存在 interval 里，fps/resolution 存在 videoSettings 里，都是控制参数却分在两个位置
- 导出 JSON 给别人看时，要同时理解两个字段的关系

### 应该怎么做
重新设计数据模型：要么**把 settings 合入 interval**，要么**把 interval 改名为 videoResult，然后把 result + params 放在一起**：

```typescript
// 方案A: 合并 → 扩展 interval
interface VideoInterval {
  id: string
  // 原有字段
  duration: number
  motionStrength: number
  videoUrl?: string
  videoPrompt?: string
  status: 'pending' | 'generating' | 'completed' | 'failed'
  // 新增
+ mode: VideoGenerationMode   // 之前没有，现在明确
+ fps: number
+ width: number
+ height: number
+ keyframes?: TimedKeyframe[]   // MKR 用：所有帧的时间位置
+ backgroundImage?: string      // MSR 用
+ gridType?: number             // MKR Grid 用
+ frameIndexes?: number[]       // MKR Grid 用
}
```

### 与现有数据的兼容性
`interval` 现在是可选字段（`shot.interval?`），旧项目没有这个字段。新增字段都有默认值：
- mode = 'basic' → 走原有逻辑，完全兼容
- fps = 30, width/height 从 aspectRatio 推断 → 与原有行为一致
- keyframes 为空 → 退化为首尾帧，与原有行为一致

## 发现 2：无 undo/redo 系统，参数调整不可回退

### 问题
我查了全项目，**没有 undo/redo 机制**。用户调整 videoSettings → 生成 → 不满意 → 继续调 → 发现之前的好，但回不去了。

现有 `updateShot` 直接修改 zustand store 中的 shot，不可逆。

### 后果
- 用户不敢尝试新参数组合，因为调了就改不回去
- 一个误操作（比如删了所有中间帧）无法撤销
- "自定义工作流"缺少安全网

### 需要建立的基建设施
```typescript
// 在 store 层加一个简单的 Command 模式
interface Command {
  type: 'update_shot' | 'add_keyframe' | 'change_video_settings'
  timestamp: number
  undo: () => void
  redo: () => void
}
```
但这个本身就是一个独立的需求，复杂度不低。**我现在不会把它加到方案里**，但必须在方案中注明"本功能与 undo/redo 的关系：当前无 undo，参数操作不可逆，建议用户操作前先导出项目备份"。

## 发现 3：nineGrid 与高级模式的关系未定义

### 当前逻辑 (index.tsx:352-354)
```typescript
const isNineGridMode = (
  shot.nineGrid?.status === 'completed' && 
  shot.nineGrid?.imageUrl && 
  sKf?.imageUrl === shot.nineGrid.imageUrl
)
```
如果符合九宫格模式，`buildVideoPrompt` 会把九宫格整图作为视觉参考。

### 问题
方案没说九宫格模式下，高级面板应该怎么表现：
- 用户用 MKR 模式时，九宫格还是"启用"状态？九宫格的格子（9张图）放进 MKR 的 3~5 个时间槽怎么映射？
- 如果九宫格状态下只允许 MSR（因为只有一张整图），需要 UI 限制还是后端报错？
- 九宫格状态下，`timedKeyframes` 应该指向九宫格子图还是原图？

### 应该怎么做
**圈定范围：本方案第一版不处理九宫格 + 高级模式的组合。** 当 `isNineGridMode === true` 时，锁定为 basic 模式，不可切换到高级 Tab。用户必须先"解除九宫格"才能使用高级模式。这个限制在 UI 上必须明确展示。

## 发现 4：`handleGenerateVideo` 的签名缺陷

### 当前签名
```typescript
const handleGenerateVideo = async (
  shot: Shot, 
  aspectRatio: AspectRatio = '16:9', 
  duration: VideoDuration = 8, 
  modelId?: string
) => {
```

### 问题
这个函数在 `index.tsx:328` 定义，在 `index.tsx:1347` 传给 VideoGenerator。它只接受 4 个参数，根本没有传递 fps/resolution/mode 的渠道。

如果高级面板生成的视频调用了这个函数，高级参数就被悄悄丢掉了。

### 应该怎么做
方案必须有**两条路径**：
1. 基本 Tab → 走现有 `handleGenerateVideo`（一个字不改）
2. 高级 Tab → 走新的 `handleAdvancedGenerateVideo`（新函数），它的签名能接收所有高级参数

两条路径在 `index.tsx` 里是独立的，互不干扰。

## 发现 5：buildKeyframePrompt bug 的波及范围

### 当前 bug
`buildKeyframePrompt`（index.tsx:242）把生成的完整 prompt 写回了 `visualPrompt`。如果高级 Tab 也调用了这个函数，bug 会污染高级模式下的数据。

### 解决方案
**高级 Tab 不用 `buildKeyframePrompt`**，自己建一套 prompt 组装逻辑（`buildAdvancedVideoPrompt`）。这条新路径从零开始，不碰 `visualPrompt`，彻底绕过 bug。

但要注意：用户可能期望"我在基本 Tab 编辑的 visualPrompt 能带到高级 Tab"。两个 prompt 编辑区要保持同步还是独立？我的选择：**独立**。基本 Tab 的编辑影响 `keyframe.visualPrompt`，高级 Tab 的编辑影响一份独立的 `interval.videoPrompt`。

## 发现 6：预设系统的盲点

### 6.1 预设的作用粒度
我的方案说"预设不保存提示词内容"，但用户的"自定义流程"可能包含提示词模板：
```
"战争场面：{actionSummary}，镜头运动：{cameraMovement}，节奏：快速"
```
用户可能想要一个"战争模式预设"和一个"文戏模式预设"，前者用一个 aggressive 的 prompt 模板，后者用平静的。

**建议**：预设分两级：
- **参数预设**：只存 fps/resolution/model/mode（当前方案）
- **全量预设**：上述 + prompt 模板 + 额外设置（作为后续扩展点）

### 6.2 预设的版本兼容
如果 API 新增了参数（比如 `motion_blur` 或 `film_grain`），今年保存的预设到明年就缺参数了。现有 adapter 会在参数缺失时使用默认值，所以不会崩，但效果可能变了。

**建议**：预设保存 `version: number` 字段，加载时做版本迁移（类似已有 `veo-r2v → veo` 迁移）。

### 6.3 预设的作用范围
- 项目级：存在 `ProjectState.videoPresets[]`，随项目 JSON 一起导出 ← 合适
- 用户级：跨项目复用，存在哪里？一个新 store？← 需要决策，第一版可以不做

## 发现 7：Tab 切换的状态保持

### 问题
用户切到高级 Tab → 调好参数 → 生成 → 切回基本 Tab 查看 → 再切回高级 Tab → 参数还在不在？

如果参数在 `AdvancedVideoPanel` 的 `useState` 里，组件卸载就丢了。如果存在 `shot.videoSettings` 里，切回来能恢复，但每次调整都写 store，性能浪费。

### 方案
- 参数「暂存」在组件本地 state 中（不写 store，性能好）
- 当用户点"生成"时，才一次性写入 `shot.videoSettings` 并触发生成
- 当组件挂载时，从 `shot.videoSettings` 恢复（如果存在）
- 用户点"重置"时，清空本地 state 回到默认值

这样既保证了性能，又保证了 Tab 切换不丢状态。

## 发现 8：adapter 的能力边界未知

### 问题
我的方案假设 callMkr / callMkrGrid 已经在 adapter 中可用。让我检查一下调用的实际情况...

从之前的搜索可以看到 `callDramaBackendVideoMkrApi` 在 `/Users/wl/Desktop/job/learn/WL-AI-Director/services/adapters/imageAdapter.ts:1851`，`callDramaBackendVideoMkrGridApi` 在 `imageAdapter.ts:1752`。

但它们都是 adapter 层面的函数，**没有经 `videoService` 的轮询/异步处理包装**。也就是说：
- 基本模式走的 BigModel 异步流程（创建任务 → 轮询 → 下载）
- MSR 走的 Drama Backend + 前端直接等待响应
- MKR/MKR Grid 目前只在 imageAdapter 里有直接调用，没有被 `videoService` 统一管理

### 后果
高级面板生成的视频可能没有统一的进度显示、没有自动重试、没有下载管理。

### 应该怎么做
建一个 `VideoGenerationOrchestrator`，统一管理所有模式的异步流程：
```
                  ┌─ basic → videoService.generateVideo()
                  │            ↓
统一入口 → route   ┼─ msr   → callMsr() + 轮询
                  │            ↓
                  └─ mkr   → callMkr() + 轮询
                               ↓
                         统一返回 {videoUrl, status}
                         写入 shot.interval
```

## 发现 9：自定义流程的"流程"是什么？

### 用户原话
> 用户在找到最适合的流程以后，可以自定义一套流程，来辅助提高效率

### 我的预设方案只做了"静态参数保存"
预设 = { fps, resolution, mode, modelId }，这只是"设置快照"。

### 真正的"流程"可能更复杂
```
"流程" 可能 = [
  step1: 切换生成模式为 MKR
  step2: 自动添加中间帧（每隔 25% 一个）
  step3: 设置 fps=30, 分辨率=1920×1080
  step4: 点击生成
  step5: 生成完成后自动播放预览
]
```

或者更复杂的：
```
"工作流" = {
  条件: 镜头类型 === "战争场面"
  动作: [
    使用预设 "hd_war_scene"
    触发一次 video enhancement （如果 API 支持）
    完成后标记该镜头的视频状态为"待审"
  ]
}
```

### 结论
第一版不要碰"流程"这个概念。**先做好参数预设**，让用户能一键恢复常用设置。等用户用熟了，自然会提出"我每次都要做这5步，能不能一键执行"，那时候再做流程引擎。

## 发现 10：导出校验 — 能否落盘 + 恢复

### 落盘路径
```
用户操作 → zustand store.updateShot() → saveProjectToDB (IndexedDB)
                                         → exportProjectData (JSON)
```

### 逐项校验

| 新数据 | 能否 IndexedDB | 能否 JSON | 能否恢复 | 风险 |
|--------|:-:|:-:|:-:|------|
| `shot.videoSettings`（或合入 interval） | ✅ 纯 JSON 对象 | ✅ 纯 JSON | ✅ | 无，结构是 js plain object |
| `ProjectState.videoPresets` | ✅ 数组 | ✅ JSON 数组 | ✅ | 无 |
| `interval.keyframes` (TimedKeyframe[]) | ✅ | ✅ | ✅ | 但要维持 `keyframeId` 引用的完整性 — 如果对应 keyframe 被删了，就是悬空引用 |
| Large base64 video data | ✅ IndexedDB 可存 | ⚠️ JSON 体积爆炸 | ✅ | 已有问题，不扩大 |

### 悬空引用问题
```json
{
  "interval": {
    "keyframes": [
      { "keyframeId": "kf_002", "positionPercent": 25 }
    ]
  },
  "keyframes": [
    { "id": "kf_002", "type": "start" }
    // 用户删了这个 keyframe！但 interval 还引用它
  ]
}
```
**后果**：高级面板加载时，`TimedKeyframe.keyframeId` 在 `shot.keyframes[]` 中找不到，会渲染一个空帧。

**对策**：加载时做一次健康检查，过滤掉引用不存在的 keyframe。如果所有中间帧都失效，降级为 basic 模式。
