# "Skill" 概念深度解析 — 以 LibTV Agent 为例

> 来源: 量子位文章《100+Skills导演级专家真·随叫随到！》
> 对比: WL AI Director 当前能力

---

## 一、LibTV Agent 的 Skill 是什么

LibTV Agent 的 **Skill** 不是"技能"的泛称，而是**封装了专业创作方法论的可复用工作流单元**。

### 核心定义

```
Skill = 特定创作场景的完整专家知识包
       ├── 风格/年代的美学理解       （如：伊斯特伍德西部片、赛博朋克）
       ├── 镜头语言模板              （如：牛仔决斗的运镜节奏）
       ├── 提示词结构模板            （如：西部片的 prompt 模式）
       ├── 色调/光影/氛围参数         （如：粗粝荒凉、风沙、冷峻光影）
       ├── 节奏/编辑规则             （如：慢推镜→快速剪辑→定格）
       └── 业内最佳实践的流程封装     （如：先角色图→场景图→分镜→视频→精修）
```

**用一句话说**: Skill 是一个"AI 导演"，你不懂西部片不要紧，选 Western Skill，它就帮你全搞定。

### 文章中出现的 Skill 示例

| Skill 名称 | 领域 | 封装了什么 |
|-----------|------|-----------|
| 伊斯特伍德西部片 | 影视风格 | 西部美学、风沙/光影/对白风格、孤胆英雄叙事 |
| 一键爽感轰炸流汽车TVC | 商业广告 | 车身光影/机械特写/城市夜景/快节奏剪辑 |
| 复古质感职场影片 | 用户自定义 | 《穿普拉达的女王》风格、时尚职场节奏 |
| 专业短剧/漫剧 | 短剧 | 对应 Skill 封装了短剧的叙事节奏和风格 |

## 二、Skill 在项目中如何起作用

### 2.1 调用流程

```
用户在 Agent 对话框选 Skill
  ↓
Skill 加载 → Agent 自动获得该领域的专家知识
  ↓
用户输入一句话想法（或上传参考图）
  ↓
Agent 按 Skill 封装的流程自动执行：
  1. 出角色概念图 → 锁定角色一致性
  2. 出场景概念图 → 锁定视觉风格
  3. 生成分镜脚本（含镜号/景别/运镜/时长/提示词）
  4. 批量生成视频片段
  5. 自动剪辑拼接成片 + 字幕 + BGM
  ↓
用户在画布上微调：哪里不对直接改，Agent 按修改意图局部重做
  ↓
最终导出成片
```

**关键特征**: 全流程在**同一个网页、同一个 Agent** 中完成，**不切工具**。

### 2.2 Skill 的三个能力层级

| 层级 | 能力 | 文章中的体现 |
|------|------|------------|
| L1: 参数预设 | 保存一组常用参数（模型/分辨率/时长） | Skill 包含各领域的最佳参数 |
| L2: 流程封装 | 定义步骤执行顺序和依赖关系 | 先角色→场景→分镜→视频的不可逆流程 |
| L3: 专家知识注入 | 注入领域特有的美学/节奏/风格知识 | 西部片的"粗粝荒凉感"、汽车广告的"光影质感" |

**当前 WL AI Director 的 Preset 停留在 L1**。LibTV Agent 的 Skill 达到了 L2+L3。

### 2.3 用户自定义 Skill

用户不只是"使用"Skill，还可以**创建自己的 Skill**：

```
用户创建一个 Skill = 
  1. 选一个基础模板（或从零开始）
  2. 写清楚：
     - 要完成什么任务
     - 怎么执行（步骤）
     - 输出什么内容
  3. 保存 → 以后可反复调用

效果: 用户跑通一次工作流后，把整个流程保存为 Skill，
       以后做同类视频一键复用。
```

## 三、对标到 WL AI Director 的能力映射

### 3.1 我们有什么

```
WL AI Director 的 Preset（当前设计）
├── 保存 Pipeline 各环节参数          ← L1 参数预设
├── 不覆盖关键帧数据/台词/角色站位     ← 只保存"设置快照"
└── 应用时自动填充各卡片               ← 一键应用
```

### 3.2 我们缺什么

| 能力维度 | LibTV Agent | WL AI Director | 差距 |
|---------|-------------|----------------|------|
| Skill 数量 | 100+（官方持续更新） | 0 | ❌ 完全缺失 |
| 领域知识注入 | Skill 封装了专业美学/风格/节奏知识 | 无机制注入领域知识 | ❌ 完全缺失 |
| 自定义 Skill 创建 | 用户可创建自己的 Skill | 只能保存参数 | ❌ 完全缺失 |
| Skill 共享/市场 | Skill Hub 市场 | 无 | ❌ 完全缺失 |
| 流程可编排 | 节点式画布+故事板双视图 | 只有 Pipeline 固定流程 | ❌ 无编排能力 |
| 单步骤重做 | 可针对单个镜头/节点重新生成 | 无 | ❌ 完全缺失 |
| 对话式交互 | Agent 对话框驱动 | 纯 UI 操作 | ❌ 无对话式交互 |

### 3.3 但从另一个角度看

WL AI Director 有 LibTV Agent 没有的能力：

| 能力 | WL AI Director | LibTV Agent | 优势方 |
|------|----------------|-------------|--------|
| 数据持久化 | IndexedDB + 项目 JSON 导出/导入 | 云端存储 | WL 更灵活 |
| 开源可定制 | 部分开源 | 商业闭源 | WL 可定制 |
| 本地部署 | 可本地运行 | 纯云端 | WL 隐私更好 |
| 剧本→分镜映射 | 有专门的脚本解析逻辑 | 依赖 Agent 对话 | WL 更结构化 |
| 运镜编排 | CameraChoreography 结构化数据 | 依赖提示词描述 | WL 更精细 |

## 四、Skill 机制的核心启示

### 4.1 Preset 升级为 Skill 的关键转变

```
当前 Preset（参数保存）
  ├── 存的是：fps=30, model=veo, mode=mkr
  ├── 应用时：填充对应参数
  └── 不携带：领域知识

Skill（专家知识封装）
  ├── 存的是：
  │   ├── 风格锚点词（Western: "粗粝荒凉、风沙、冷峻光影"）
  │   ├── 提示词模板（"深棕色昭和军装" vs "#FFD700金色铠甲"）
  │   ├── 镜头库（西部片常用推镜/定格/宽幅构图）
  │   ├── 色调参数（色相偏移+饱和度+曲线预设）
  │   ├── 节奏规则（慢→快→定格 vs 快节奏切镜头）
  │   └── 参数预设（模型/分辨率/时长）
  ├── 应用时：注入全部知识到对应环节
  └── 体现形式：用户只感知"选风格流派"，不感知具体参数
```

### 4.2 对当前项目 Pipeline 的升级方向

```
Pipeline（当前设计 09）
├── ① 画面构图  ② 镜头语言  ③ 光照氛围  ④ 表演调度  ⑤ 成片输出
├── 每个环节用当前 shot 字段当默认值
└── 预设 = 各环节参数的静态快照

Pipeline + Skill（升级方向）
├── ① 画面构图 → Skill 带入"该风格常用构图"（西部片爱宽幅、古装剧爱对称）
├── ② 镜头语言 → Skill 带入"该风格镜头库"（西部片多推镜和慢摇）
├── ③ 光照氛围 → Skill 带入"该风格色调曲线"（西部片暖金+深蓝、赛博朋克霓虹+暗紫）
├── ④ 表演调度 → Skill 带入"该风格表演模式"（战争剧激昂、职场剧细微）
├── ⑤ 成片输出 → Skill 带入"该风格后期参数"（胶片颗粒 vs 清晰锐利）
└── Skill = 跨环节注入专业知识
```

### 4.3 Skill 的创建入口

在用户体验上，用户应该在 Pipeline 中完成一次完美创作后，一键将其保存为 Skill：

```
用户调好 Pipeline 所有环节 → 点"生成"→ 看到满意的视频
  ↓
点"保存为 Skill"
  ↓
弹窗：
  ├── Skill 名称（如"战争场景 - 黄昏悲壮"）
  ├── 所属分类（如"史诗/战争"）
  ├── 封面图（从生成视频中选一帧）
  └── 确认保存
  ↓
下次开始新镜头或新项目时，在 Pipeline 顶部选 Skill，
  → 所有环节自动注入对应风格
```

### 4.4 与 LLM 驱动的差异

LibTV Agent 的 Skill 是**人工编排的**（由专业导演/专业团队设计封装），不是 LLM 自动生成的。这意味着：

- LLM 负责：执行 Skill 的具体步骤（生成 prompt、调用 API）
- Skill 负责：告诉 LLM 应该用什么**思路**、按什么**顺序**、带什么**领域知识**
- 两者结合：LLM 的灵活性 + Skill 的专业确定性

## 五、对当前项目的实际建议

Skill 的概念可以直接映射到我们已有的设计：

| 我们的已有设计 | 升级方向 | 借鉴程度 |
|-------------|---------|---------|
| Pipeline 预设（08/09 方案） | → Skill（L1→L2+L3） | 🔴 建议做，核心差异化 |
| A01：领域知识注入机制 | → Skill 承载领域知识 | 🟡 必须与 Skill 一起设计 |
| A02：提示词术语缺失 | → Skill 携带风格锚点词库 | 🟡 由 Skill 解决 |
| B06：角色不一致 | → Skill 携带 Character DNA 参考 | 🟢 Skill 可以约束统一风格 |
| D05：多后端统一管理 | → Skill 决定路由策略 | 🟢 Skill 可包含模型选择规则 |

**关键决策**: 
- 如果做 Skill，之前设计的 Preset 就变成 Skill 的一个子集（参数层）
- Skill 必须要有**创建 UI** + **应用 UI** + **管理 UI**（列表/分类/搜索）
- 第一版的 Skill 可以只做"封装 Pipeline 环节参数+风格锚点词"，不做节点编排

---

## 六、一句话总结

> **Skill = 专业导演的创作方法论封装。它不是参数预设，是把"怎么拍好西部片"的全部经验打包成一个可复用的模块。**
> 
> WL AI Director 的 Pipeline 预设目前停留在"存参数"层级，向 Skill 升级意味着要增加"领域知识注入"、"风格锚点词库"、"镜头模板库"三个维度的能力。
