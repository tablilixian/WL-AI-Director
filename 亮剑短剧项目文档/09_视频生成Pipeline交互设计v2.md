# 视频生成功能扩展 — 交互设计方案 v2

> 设计原则：从导演视角出发，非工程师视角
> 核心理念：Pipeline 工作流 + 二级 UI + AI 深度辅助

---

## 一、总体交互哲学

### 1.1 两个层次

```
第一层 ─ Main Pipeline（主面板）
  ├── 显示完整的拍摄工作流
  ├── 每个环节以卡片形式展示
  ├── 只显示关键信息摘要
  └── 点击卡片进入详情编辑

第二层 ─ Detail Modal（详情弹窗）
  ├── 针对某一环节的完整编辑器
  ├── 所有参数在此暴露
  ├── AI 辅助按钮嵌入其中
  └── 编辑后主面板卡片自动更新摘要
```

### 1.2 工作流分段

把"视频生成"拆成导演拍片时的 5 个自然环节：

```
 ① 画面设计  ② 镜头语言  ③ 光照氛围  ④ 表演调度  ⑤ 成片输出
(Frame)     (Camera)    (Lighting)  (Action)    (Output)
```

每个环节对应一个卡片，从上到下排列，形成 Pipeline。

## 三、各环节的详细交互设计

### 3.1 ① 画面构图 (Frame)

**主面板展示**:
```
[首帧缩略图] → [中间帧缩略图] → [尾帧缩略图]
                  ↑ 可拖拽调整位置
摘要: "首帧(近景)+2中间帧(中景/全景)+尾帧(大全景)"
```
**系统行为**: 根据关键帧数量自动决定后端模式
- 1帧 → MSR
- 2帧 → MKR (首尾插值)
- 3~5帧 → MKR (完整多关键帧)

**Modal 内**:
- 时间轴视图，关键帧在时间线上排列
- 拖拽调整每个帧的时间位置
- 点击帧缩略图进入该帧的视觉 Prompt 编辑器
- "添加中间帧"按钮：支持2种来源
  - 从已有关键帧中选（shot.keyframes）
  - 让 AI 生成一帧（LLM 描述 → T2I 生成）
- AI 按钮：
  - "根据动作描述推荐关键帧位置"
  - "自动补全缺失的过渡帧"

### 3.2 ② 镜头语言 (Camera)

**数据来源**: `shot.shotSize`, `shot.cameraMovement`, `shot.cameraChoreography`

**主面板摘要**:
```
景别: 近景→全景 (变化)
运镜: 推轨 + 上摇, 中速
角度: 仰拍→平视
```

**Modal 内 — 结构化编辑器**：

```
┌─ 起点 ────────────────────── 终点 ──────────┐
│ 景别: [近景 ▼]             景别: [全景 ▼]   │
│ 角度: [仰拍 ▼]             角度: [平视 ▼]   │
│ 主体位置: [左侧1/3]        主体位置: [居中]  │
│ 焦点: [浅景深]             焦点: [深焦]      │
├────────── 运动路径 ──────────────────────────┤
│ [推轨] + [上摇]            速度: [中速 ▼]   │
│ 强度: ═══●══════════ 0.7                    │
├────────── AI 辅助 ───────────────────────────┤
│ [↗ 根据动作描述生成运镜方案]                  │
│ 输入: "李云龙在战场上指挥冲锋"                │
│ 输出: "推轨跟随+仰拍, 中速, 从全景推到中近景" │

```

AI 辅助的输入字段：用户输入一句话动作描述 → AI 输出完整的 `CameraChoreography` 结构。

## 四、AI 辅助的触发点汇总

| 环节 | AI 按钮 | 输入 | 输出 | 方式 |
|------|---------|------|------|------|
| ① Frame | 推荐关键帧位置 | 动作描述 + 时长 | 各帧时间百分比 | 即时填充 |
| ① Frame | 补全过渡帧 | 首尾帧 | 中间帧描述 | 生成描述 → 用户确认 |
| ② Camera | 生成运镜方案 | 动作描述 | CameraChoreography 完整结构 | 即时填充 |
| ③ Lighting | 丰富光照描述 | 场景关键词 | 详细照明文本 | 即时填充 |
| ③ Lighting | 匹配场景氛围 | shotSize + actionSummary | 推荐的氛围+时间 | 即时填充 |
| ④ Performance | 丰富动作细节 | 当前 actionSummary | 扩展后的动作描述 | 即时填充 |
| ④ Performance | 生成台词 | 角色 + 场景 | 符合人物性格的台词 | 即时填充 |
| ⑤ Output | 优化提示词连贯性 | 各环节合成的 prompt | 优化后的完整 prompt | 即时填充 |
| ⑤ Output | 翻译为英文 | 中文 prompt | 英文 prompt | 即时填充 |

每个 AI 按钮都遵循：
1. 调用时显示 loading
2. 结果直接填入对应字段（不覆盖用户已编辑内容）
3. 用户可继续手动修改

## 五、技术模式对用户透明

### 后端自动路由

用户不需要知道 MSR / MKR / MKR Grid 的区别。系统根据用户在 Pipeline 中的设置自动选择：

```
用户在①画面构图中的操作 → 自动决定模式
├── 只有首帧 → MSR (单图+prompt)
├── 首帧+尾帧 → MKR (首尾插值)
├── 3~5帧 → MKR (多关键帧)
└── 九宫格 → MKR Grid (宫格视频)
```

在⑤输出卡片的"技术设置"弹窗中，可以**查看**当前选中的模式。但默认不暴露给普通用户。

### 默认值 + 智能推测

每个参数都有默认值，且可以从现有数据推测：
- 景别 → 从 `shot.shotSize` 读取
- 运镜 → 从 `shot.cameraMovement` 读取
- 结构化运镜 → 从 `shot.cameraChoreography` 读取
- 动作 → 从 `shot.actionSummary` 读取
- 台词 → 从 `shot.dialogue` 读取
- 角色 → 从 `shot.characters` + 资产库读取

用户什么都不改，直接点"生成"，效果应该和当前基本模式一致。

## 七、与现有功能的关系

### 7.1 兼容性

| 场景 | 行为 |
|------|------|
| 旧项目加载 | interval 无 mode 字段 → 默认 'basic' → pipeline 不显示 |
| 新 Pipeline 生成后切回 Tab | interval 中的设置保留，下次点开 Pipeline Tab 恢复 |
| 用户点"重新生成" | 读取 interval.mode，按对应模式重新调用 |
| 用户删了中间帧 | 加载 interval.keyframes 时做健康检查，失效帧自动移除 |

### 7.2 两条生成路径

```
基本 Tab → handleGenerateVideo (index.tsx:328) → 一字不改
高级 Tab → handlePipelineGenerate (新函数) → 新路径
```

两条路径结果都写入 `shot.interval`，后者写入更多字段。当用户在高级 Tab 点"生成"后，切换到基本 Tab 也能看到视频预览（因为 `interval.videoUrl` 已经写入了）。

## 九、UI 交互细节

### 9.1 卡片状态

每个卡片有 3 种状态：

```
🟢 已配置（有数据）
  显示摘要信息，可点击编辑

⚪ 未配置（无数据，使用默认值）
  显示"点击配置"，灰色提示文字

🔄 AI 生成中
  Loading 动画
```

### 9.2 编辑流程

```
点击卡片 → Modal 弹出 → 编辑 → 确认
                            ↓
                      主面板卡片更新摘要
                        
未确认前，主面板不变（保持上次状态）
确认后，数据写入内存（暂不写 store）
点"生成"时，统一写入 shot.interval + 触发 API
```

### 9.3 键盘快捷键

```
Enter → 确认 Modal
Esc → 关闭 Modal
Cmd+Enter → 从任意卡片直接开始生成
```

## 十、总结：v1 与 v2 对比

| 维度 | v1（原始方案） | v2（Pipeline 方案） |
|------|--------------|-------------------|
| 视角 | 开发者/参数面板 | 导演/拍摄工作流 |
| 核心概念 | MSR/MKR/MKR Grid 模式 | Frame/Camera/Lighting/Performance/Output |
| AI 辅助 | 未考虑 | 每个环节都有 AI 按钮 |
| 技术细节 | 用户需要选择模式 | 系统自动路由，用户不感知 |
| 数据模型 | videoSettings 与 interval 分离 | 合入 interval |
| UI 复杂度 | 参数列表平铺 | 二级 UI（卡片摘要 + Modal 详情） |
| 与现有功能关系 | 独立 Tab | 独立 Tab + 兼容旧数据 |
