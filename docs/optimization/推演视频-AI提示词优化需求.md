## 一、背景与问题分析

### 1.1 现状概述

"推演→视频"是一条 5 阶段 AI 管线（确认源图 → AI 分析 → 剧情推演 → 宫格生成 → 生成视频），用户从一张静态关键帧出发，全自动生成一段连续剧情视频。

### 1.2 核心痛点

当前流程中，存在 **4 个提示词输入入口**，对普通用户形成明显的使用门槛：

| 痛点 | 具体表现 | 受影响用户群 |
|------|---------|------------|
| **提示词写作能力弱** | 用户不熟悉影视摄影术语，不知道如何专业地描述画面、镜头、剧情走向 | 90%+ 的普通创作者 |
| **想法到提示词的转化断层** | 用户只有一个模糊的想法（如"骑兵从山谷跑过"），无法将其转化为结构化的分镜描述 | 所有非专业用户 |
| **提示词质量不可控** | 用户手动编写的提示词质量参差不齐，直接影响 AI 生成结果的质量，容易产生挫败感 | 新用户 |
| **被预设结构束缚** | "起承转合"等固定模板不适合所有场景（如固定机位拍摄的单一镜头），限制了用户的创作自由度 | 所有用户 |

### 1.3 问题定位：4 个关键优化点

经过代码审查，确定以下 4 个位置是用户体验的瓶颈：

| # | 步骤 | 输入项 | 当前状态 | 痛点 |
|---|------|--------|---------|------|
| **P1** | Step 2 - AI 分析 | 系统提示词（System Prompt） | 默认提供一段通用模板，支持手动编辑 | 用户不会写专业的影视分析指令 |
| **P2** | Step 2 - AI 分析 | 用户提示词（User Prompt） | 根据勾选维度自动生成，支持补充自定义内容 | 用户不知道如何补充有价值的约束条件 |
| **P3** | Step 3 - 剧情推演 | 剧情方向（narrativeDirection） | 纯自由文本输入 + 预设的"起承转合"分镜模板 | **最大痛点** — 用户只能用简单白话描述，且被固定模板限制；例如"骑兵从山谷跑过"是一个固定机位的单一镜头，套不进起承转合 |
| **P4** | Step 5 - 生成视频 | 关键帧 visualPrompt | 自动组装（景别 + 机位 + 动作 + 风格），可手动编辑 | 用户想调整 prompt 但不知道怎么写更有效 |

## 二、优化方案总览

### 2.1 核心思路

> **在每个提示词输入框旁增加一个「AI 优化」按钮，用户输入粗略想法 → 一键调用 LLM 优化为专业提示词 → 优化结果以独立可编辑区域展示，用户可对比、编辑后使用。**

### 2.2 设计原则

1. **透明可控**：原始输入和 AI 优化结果双栏独立展示，用户完全可视、可对比、可自由编辑
2. **原地操作**：不弹出新面板、不打断当前流程，在输入框下方展开优化结果区域
3. **保留原文**：原始输入始终保留不动，作为对比基准和重新生成的依据（**已确认**）
4. **默认可见**：优化按钮始终默认展示，用户需要时即可使用（**已确认**）
5. **智能感知**：根据当前步骤的上下文（前序步骤的分析结果、勾选的维度等），生成有针对性的优化
6. **灵活结构**：不预设镜头关系模板，"起承转合""渐进推进"等由 LLM 根据用户意图自由决定（**v1.2 新增**）

### 2.3 通用 UI 模式

所有优化点的交互模式统一为 **"原始输入保留 + 优化结果可编辑 + 支持重新生成"** 的双栏模式：

```
┌──────────────────────────────────────────────┐
│ 标签名称                                      │
│                                               │
│ ┌─ 原始输入 ────────────────────────────────┐│
│ │ 用户输入的简单想法...（始终可编辑）          ││
│ │                                             ││
│ └───────────────────────────────────────────┘│
│                                               │
│ [AI 优化]              ← 点击后按钮变为 loading│
│                                               │
│ ┌─ AI 优化结果 ── [↻ 重新生成] ────────────┐│
│ │ 优化后的专业提示词（可自由编辑）...          ││
│ │                                             ││
│ │ (此区域为可编辑 textarea，修改后即为最终     ││
│ │  使用的提示词内容)                           ││
│ └───────────────────────────────────────────┘│
└──────────────────────────────────────────────┘
```

**关键交互规则**：

| 状态 / 操作 | 行为 |
|------------|------|
| **初始态** | 原始输入框（可编辑），AI 优化结果区域隐藏 |
| **点击「AI 优化」** | 按钮变为 loading 状态，调用 LLM 优化。原始输入保持可编辑 |
| **优化完成** | AI 优化结果区域展开，显示优化后文本（可编辑 textarea）。原始输入不变 |
| **用户编辑优化结果** | 直接在优化结果 textarea 中修改，修改后的内容即作为最终使用的提示词 |
| **点击「↻ 重新生成」** | 基于**原始输入的当前内容**重新调用 LLM，用新结果覆盖旧优化结果 |
| **用户修改原始输入后再次优化** | 原始输入始终可编辑。修改后可再次点击「AI 优化」基于新原文重新生成 |

**核心设计决策（已确认）**：
- **保留原始输入**：原始文本框始终存在，作为对比基准和重新生成的依据
- **优化结果可编辑**：优化结果以可编辑 textarea 展示，用户直接修改即生效
- **支持重新生成**：基于原始输入重新优化，覆盖旧的优化结果
- **不替换原输入框**：不做原地替换，而是下方展开新区域展示优化结果。两个区域独立存在
- **暂不支持"换一种风格"**：Phase 1 先上基础版，后续可扩展

## 三、各步骤详细优化设计

### 3.1 【P1/P2】Step 2 - VLM 画面分析提示词优化

#### 目标
帮助用户将模糊的分析需求转化为专业的影视镜头分析指令。

#### 输入框位置

**System Prompt 输入框**  
**User Prompt 补充输入框**

#### "AI 优化"行为定义

##### System Prompt 优化规则（P1）

| 场景 | 用户输入 | AI 优化方向 |
|------|---------|------------|
| 默认状态 | 默认模板 "你是一个专业的影视镜头分析师..." | 根据已勾选的维度（selectedAspects），生成更精准的角色定义，例如增加"请特别关注色彩对比和光影层次" |
| 用户已修改 | 用户改写的 System Prompt | 保留用户意图，补充专业术语和结构化输出要求 |

**System Prompt 优化 LLM 调用参数**：
```
system: "你是一个 Prompt Engineering 专家，擅长优化 AI 视觉分析的系统提示词。"
user prompt: "请将以下系统提示词优化为更专业、更结构化的版本，用于指导 VLM（视觉语言模型）分析影视画面。
当前已选择的画面分析维度：[selectedAspectsLabel]
原始提示词：[用户输入的 system prompt]
要求：
- 使用专业影视/摄影术语
- 明确输出格式要求
- 针对已选的 N 个维度给出具体分析指引
- 保持简洁，不超过 300 字"
```

##### User Prompt 补充优化规则（P2）

| 场景 | 用户输入 | AI 优化方向 |
|------|---------|------------|
| 用户只写了简单要求 | "画面要暖色调" | 扩展为专业表述："画面整体应呈现暖色调氛围，色温控制在 3500-4500K，以橙黄为主基调，弱化冷色系。主体面部应有柔和暖光补光，阴影区域略带琥珀色。" |
| 用户未写额外要求 | （空） | 基于勾选的维度生成补充要求，例如"请确保分析覆盖所有选中的维度，不要遗漏。" |

### 3.2 【P3】Step 3 - 剧情推演方向优化（最高优先级）

#### 目标
这是 **优先级最高的优化点**。将用户的白话想法转化为专业的电影分镜语法，是提升最终视频质量的杠杆点。

#### 核心体验改进

**Before（当前）**：
> 用户输入："骑兵从山谷跑过"  
> → 强制套用"起承转合"模板，与实际意图脱节

**After（优��后）**：
> 用户输入："骑兵从山谷跑过"  
> → 点击「AI 优化」  
> → LLM 理解意图为"固定机位的单一运镜"，生成对应 4 帧描述  
> → 用户可审阅编辑后使用

#### 设计理念：不预设结构

**核心原则**：15 秒、4 个镜头的视频承载不了完整的叙事弧线。4 帧是同一段画面在时间轴上的 4 个取样点（而非 4 个独立的情节点）。镜头之间的关系——是固定机位的时间推进、是空间景别的递进、是氛围渐变、还是慢动作拉伸——**完全由 LLM 根据用户的自然语言意图自由决定**，不做任何预设。

| 用户的意图 | LLM 可能推演的结构 |
|-----------|------------------|
| "骑兵从山谷拐弯处跑过来" | 固定机位 × 4 个时间点（远 → 中 → 近 → 掠过镜头） |
| "主角发现古书，蓝光乍现" | 空间递进（环境建立 → 主体引入 → 关键物体特写 → 反应镜头） |
| "雨天街角，一个红伞女人走过" | 氛围渐变（雨景建立 → 伞入画 → 侧身经过 → 背影远去） |
| "爆炸慢镜头：玻璃碎片飞溅" | 时间拉伸（引爆瞬间 → 碎片扩散 25% → 50% → 100%） |

#### 输入框区域设计

```
┌──────────────────────────────────────────────┐
│ 剧情方向                                      │
│                                               │
│ 用自然语言描述你想拍摄的画面，                │
│ 可以是一段剧情、一个镜头、一种氛围...          │
│                                               │
│ ┌───────────────────────────────────────────┐│
│ │ 骑兵从山谷拐弯处跑过来...                  ││
│ └───────────────────────────────────────────┘│
│                                               │
│ [AI 优化]                                     │
│                                               │
│ 怎么写？试试这些表达方式：                     │
│ ┌───────────────────────────────────────────┐│
│ │ "骑兵队列从山谷远处跑来，镜头固定不动"     ││
│ │ "深夜书房，主角发现古书后蓝光亮起"         ││
│ │ "雨夜街角，一把红伞逐渐消失在雾中"         ││
│ │ "爆炸瞬间，碎片飞溅的慢镜头"               ││
│ └───────────────────────────────────────────┘│
│                                               │
│ ┌─ AI 优化结果 ── [↻ 重新生成] ────────────┐│
│ │ (优化后文本，可编辑)                       ││
│ └───────────────────────────────────────────┘│
└──────────────────────────────────────────────┘
```

- 用户输入框上方有引导文字："用自然语言描述你想拍摄的画面，可以是一段剧情、一个镜头、一种氛围..."
- 输入框下方有"意图范例"区域（4 条折叠显示的示例），帮助用户理解如何表达
- 范例覆盖不同的镜头类型（固定机位/空间推进/氛围渐变/时间拉伸），但不作为输出约束

#### "AI 优化"行为详解

**输入来源**（发送给优化 LLM）：
- 用户输入的原始"剧情方向"
- Step 2 的 VLM 分析结果（vlmRawAnalysis / schema）

> **为什么不需要传入图片？**  
> 推演流程的第一步（Step 2）已经通过 VLM 对图片做了详细的画面分析（10 个维度的结构化描述）。这些分析结果——主体、构图、光影、色彩、环境等——已经足够精准地描述了图片内容。优化 LLM 基于这些文本分析结果工作，不需要再次看图片。这避免了多模态调用的额外复杂度和延迟。

**优化 LLM 的 System Prompt**（v1.2 重写）：
```
你是一位资深电影导演和分镜师。

用户会给你一段"剧情方向"的自然语言描述——可能是完整的剧情、一个镜头想法，或者一种氛围感受。这是给一段 15 秒、4 帧的短视频用的，请将其优化为一段专业的电影级叙事描述，用于指导 AI 推演这 4 帧分镜。

核心原则：
1. 不要预设结构。不要套用"起承转合""渐进推进"或任何固定模板。
   4 帧是同一段画面在时间轴上的 4 个连续取样点，不是 4 个独立情节。
   根据用户意图，自主决定 4 帧的逻辑关系：可能是固定机位的时间推进、可能是景别的空间递进、可能是氛围的渐变、可能是慢动作的时间拉伸……

2. 在展开描述前，先判断用户意图属于什么类型：
   - 如果用户描述的是"固定镜头里发生了一件事"，则保持固定景别/机位，仅推进画面内的动作和状态
   - 如果用户描述的是"从 A 到 B 的变化"，则按空间/情感递进安排帧序
   - 如果用户描述的是一个"瞬间"，则用时间拉伸的方式拆分微动作
   - 如果拿不准，保持简洁，不做过度解读

3. 结合当前画面的 VLM 分析结果，确保推演从该画面出发具有视觉连续性

4. 每帧描述要包含具体的视觉要素：
   - 景别（根据意图自然选择，不一定每帧都变）
   - 画面中正在发生什么
   - 光线/色调/氛围的延续或变化
   - 运镜方式（固定机位完全 ok）

5. 控制字数在 300-500 字

如果用户提供了画面分析结果，请参考：
---
[VLM 分析结果]
---

输出格式（结构字段固定，内容灵活）：

## 意图理解
（一句话判断用户想拍什么类型的镜头）

## 分镜描述
- 帧 1（0s-Ns）：[景别] [画面内容] [光线/氛围] [运镜]
- 帧 2（Ns-Ns）：同上
- 帧 3（Ns-Ns）：同上
- 帧 4（Ns-Ns）：同上

## 整体视觉建议
[光影、色调、节奏等统一性建议]
```

**优化示例**：

| 用户输入 | 意图类型 | AI 优化输出 |
|---------|---------|------------|
| "一队骑兵从山谷拐弯处骑马跑过来" | 固定机位 | **意图理解**：固定机位拍摄骑兵队列由远及近的完整过程。

**分镜描述**：
- **帧 1（0s-4s）**：远景，山谷弯道空镜，晨雾在低位飘荡，阳光从山脊后渗出形成逆光轮廓。固定机位不动。
- **帧 2（4s-7.5s）**：中远景，骑兵队列从弯道拐出，仍较小但队形清晰可见，马蹄扬起尘土在逆光中呈金色。机位不变。
- **帧 3（7.5s-11s）**：中景，骑兵主体进入画面中央区域，能看清盔甲反光和马的肌肉线条。机位不变。
- **帧 4（11s-15s）**：骑兵从镜头前掠过，前景虚化带来速度感，画面收在骑兵队列远去、尘土逐渐落定的远景上。全程固定机位无移动。

**整体视觉建议**：暖金色逆光贯穿全程，色调统一金黄偏橙；节奏由静→动→静，马蹄声和尘土是画面的主要动态元素。 |
| "主角发现古书，蓝光乍现" | 空间递进 | **意图理解**：从环境到主体到关键物体到反应的空间递进镜头。

**分镜描述**：
- **帧 1（0s-3.5s）**：全景，昏暗书房，烛台在画面一角，暖光勉强照亮四周书架。固定机位。
- **帧 2（3.5s-7s）**：中景，主角坐在桌前，手指刚触碰到一本皮质古书的封面，表情好奇。平视固定。
- **帧 3（7s-11s）**：特写，古书自行翻开，幽蓝冷光从书页间涌出，与烛光的暖黄形成强烈冷暖对比。镜头微推。
- **帧 4（11s-15s）**：中景，蓝光映在主角脸上，震惊表情，环境色温已全面转向冷蓝调。固定机位。

**整体视觉建议**：色调从暖琥珀（烛光 3500K）向冷蓝灰（蓝光 8000K+）渐变过渡；光影从散射柔光转为强烈明暗对比；节奏由慢→中→快→定格。 |

#### 交互优化点

- 输入框下方始终显示「AI 优化」按钮（**已确认：默认展示**）
- 优化完成后，下方展开"AI 优化结果"区域（可编辑 textarea），原始输入保留在上方作为对比
- 优化结果可自由编辑，编辑后的内容即为最终使用的剧情方向
- 支持**重新生成**：点击「↻ 重新生成」基于原始输入重新优化，覆盖旧结果
- 原始输入始终可编辑，修改后可再次优化
- 输入框下方增加**意图范例提示**区域（4 条常见用例），默认折叠显示，帮助用户组织语言（**v1.2 新增**）

### 3.3 【P4】Step 5 - 关键帧 Prompt 优化

#### 目标
帮助用户将自动组装的 prompt 优化得更具电影质感，提升视频生成效果。

#### 输入框位置

每帧的 `visualPrompt` textarea，每个分镜��都有一个独立的 prompt。

#### "AI 优化"行为定义

| 操作粒度 | 触发方式 | 行为 |
|---------|---------|------|
| **单帧优化** | 点击某一帧旁边的「AI 优化」按钮 | 只优化该帧的 visualPrompt |
| **全部优化** | 顶栏增加「AI 一键优化全部 Prompt」按钮 | 批量优化所有帧的 visualPrompt |

**单帧优化 LLM Prompt**：
```
system: "你是一个 AI 视频生成（Text-to-Video）的 Prompt Engineering 专家。请将下面的 prompt 优化为更高质量的视频生成提示词。"

user: "请优化以下视频生成 Prompt，要求：
- 增强画面质感和电影感
- 补充场景氛围和细节描述（质感、材质、天气、烟雾等）
- 保持原有的景别、机位、动作信息
- 运镜指令保持不变或更精准
- 总长度不超过 200 字
- 不要新增不存在的主体

当前运镜: [cameraMovement]
当前动作: [action]

```

**优化示例**：

### 4.1 公用模块设计

建议抽取一个共享的 **PromptOptimizer 服务**：

```typescript
// services/promptOptimizer.ts

interface PromptOptimizeRequest {

  rawInput: string;

interface PromptOptimizeResponse {
  /** 优化后的内容 */
  optimized: string;
  /** 原始内容备份 */
  original: string;
}

async function optimizePrompt(req: PromptOptimizeRequest): Promise<PromptOptimizeResponse> {
  // 1. 根据 type 选择对应的 system prompt
  // 2. 组装 user prompt（包含 context）
  // 3. 调用 LLM（chat 接口）
  // 4. 返回优化结果
}
```

### 4.2 组件封装

建议封装一个通用的 **OptimizableTextarea** 组件，实现双栏交互模式：

```typescript
// src/modules/canvas/components/shared/OptimizableTextarea.tsx

interface OptimizableTextareaProps {
  value: string;
  onChange: (value: string) => void;
  optimizeType: PromptOptimizeRequest['type'];
  optimizeContext?: PromptOptimizeRequest['context'];
  placeholder?: string;
  rows?: number;
  disabled?: boolean;
}
```

**组件内部状态流转**：

```
┌──────────┐   点击「AI 优化」     ┌──────────┐
│  idle    │ ─────────────────────→ │ loading  │
│ 初始态    │                        │ 优化中    │
└──────────┘                        └──────────┘
     ↑                                    │
     │ 原始输入被修改                      │ LLM 返回结果
     │ → 清空优化结果                     ↓
     │                              ┌──────────┐
     └──────────────────────────────│  done    │
        点击「↻ 重新生成」            │ 优化完成  │
        或 原始输入修改后再次优化       └──────────┘
```

**关键约束**：
- 原始输入被用户修改时，自动清空已有的优化结果（因为原文已变化，旧优化已过期）
- 优化结果区域的编辑不会影响原始输入区域
- 外部通过 `onChange` 获取的是"当前有效的提示词"（优化结果优先，否则原始输入）

### 4.3 调用的 LLM

- 复用现有的 `services/modelService.ts` 中的 `chat()` 接口
- 使用当前用户配置的 LLM 模型（通常是 GLM-4-Flash 或用户自定义）
- **无需引��新的模型依赖**

### 4.4 错误处理

| 异常场景 | 处理方式 |
|---------|---------|
| LLM 调用超时 | Toast 提示"优化请求超时，请稍后重试"，恢复输入框原文 |
| LLM 返回空内容 | Toast 提示"优化结果为空，请重试"，保留原文不动 |
| 网络异常 | Toast 提示网络错误信息，不替换原文 |
| 用户在优化中关闭面板 | 静默丢弃请求结果，不做状态更新 |
