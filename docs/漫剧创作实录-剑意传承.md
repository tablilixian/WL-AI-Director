## 1. 第一阶段：项目全景分析

### 1.1 初始问题

用户提出："帮我分析整个项目，我现在想要创作一个两分钟左右的漫剧，要怎么开始？"

此时对项目一无所知，需要完整探索。

### 1.2 探索过程

#### 第一步：读取项目根目录结构

通过 `read` 工具查看 `WL-AI-Director/`，发现这是一个典型的 Vite + React + TypeScript 项目，包含：

```
App.tsx
components/
services/
types.ts
src/
package.json
vite.config.ts
```

#### 第二步：深入探索核心文件

| 文件 | 读取目的 | 关键发现 |
|---|---|---|
| `README.md` + `README_EN.md` + `README_JA.md` | 项目定位 | 这是一个"AI 漫剧工场"，"Script-to-Asset-to-Keyframe"流水线 |
| `SPEC.md` | 功能规格 | 完整的阶段划分：StageScript → StageAssets → StageDirector → StageExport |
| `package.json` | 技术栈 | React 19, Zustand, Tailwind, PocketBase, FFmpeg WASM, i18next, Three.js |
| `types.ts` | 数据结构 | Character, Scene, Shot, Keyframe, ScriptData, CameraChoreography 等核心类型 |
| `types/model.ts` | 模型配置 | ModelType, ModelProvider, ChatModelDefinition, ImageModelDefinition 等 |
| `App.tsx` | 应用入口 | 路由逻辑、阶段切换、自动保存、Auth 流 |
| `index.tsx` | 渲染入口 | ThemeProvider + AlertProvider 包裹 |
| `vite.config.ts` | 构建配置 | React 插件，多个 API 代理 (/drama-api, /bigmodel, /edge-tts 等) |

#### 第三步：深入 AI 服务层

| 文件 | 关键内容 |
|---|---|
| `services/ai/scriptService.ts` | `parseScriptToData()` 解析故事文本 → `ScriptData`；`generateShotList()` 生成分镜头 |
| `services/ai/visualService.ts` | `generateVisualPrompt()` 生成角色/场景提示词；`generateImage()` 调用图像 API |
| `services/ai/apiCore.ts` | API 调用基础设施（重试、错误处理、流式响应、模型选择） |
| `services/ai/promptConstants.ts` | 各视觉风格的 prompt 模板（live-action, anime, ink-wash 等） |
| `services/adapters/` | chatAdapter（对话 API）、imageAdapter（图像生成）、videoAdapter（视频生成） |

#### 第四步：探索 UI 组件层

| 文件 | 关键发现 |
|---|---|
| `components/StageScript/index.tsx` | 剧本阶段主组件，含配置面板、剧本编辑器、场景分镜拆解 |
| `components/StageScript/ConfigPanel.tsx` | 项目配置面板：标题、语言、时长、模型、视觉风格 |
| `components/StageScript/ScriptEditor.tsx` | 文本编辑器，输入**故事原文**后 AI 解析 |
| `components/StageScript/SceneBreakdown.tsx` | 展示 AI 解析后的结构化场景和角色 |
| `components/StageScript/constants.ts` | 时长选项（30s/60s/120s/300s）、视觉风格（7种预设）、默认模型 |

### 1.3 核心发现：项目的工作流程

```
用户输入故事原文 (rawScript)
    ↓
parseScriptToData()  AI解析
    ↓
ScriptData (结构化: 角色+场景+故事段落+ArtDirection)
    ↓
generateShotList()  AI生成分镜头
    ↓
Shot[] (含关键帧描述)
    ↓
进入 StageAssets → StageDirector → StageExport
```

**关键认知**：项目不是让用户提供"写好的剧本格式"，而是接受**故事叙事文本**，让 AI 自己去解析成结构化数据。这意味着我之前的剧本创作方法需要调整。

## 2. 第二阶段：故事方案决策

### 2.1 三个方案的提出

基于项目目标（2 分钟漫剧 × 中国修仙题材），提供了三个不同方向：

#### 方案一：《凡尘问道》（经典逆袭流）

| 场景 | 内容 | 视觉亮点 |
|---|---|---|
| 开场 | 外门弟子被内门当众羞辱，丹药被踩碎 | 俯视/仰视对比构图，丹药碎裂特写 |
| 发展 | 深夜瀑布下独自苦修 | 月光+水雾+灵气环绕，意境拉满 |
| 转折 | 妖兽突袭宗门，众人溃逃 | 巨兽破墙而出，烟尘四起 |
| 高潮 | 他以凡人之躯挡在妖兽面前，爆发出惊天剑意 | 剑气横贯画面，衣衫破碎但眼神坚定 |
| 结局 | 掌门出手收妖，当众收他为亲传弟子 | 朝阳初升，宗门万人瞩目 |

**特点**：情节经典，观众易共鸣，每个场景视觉反差大，关键帧效果好。

#### 方案二：《剑意传承》（师徒传承）

| 场景 | 内容 | 视觉亮点 |
|---|---|---|
| 开场 | 老剑仙将残剑传予木讷少年 | 晨雾竹屋，抚剑，剑不肯出鞘 |
| 发展 | 山巅教学，少年悟剑 | 残阳云海，一剑刺出剑气破空 |
| 转折 | 仇家寻仇，云沧咳血 | 废墟煞气，少年挡在师父身前 |
| 高潮 | 剑出鞘，白光冲天，惊退强敌 | 落叶静止，剑鸣啸天 |
| 结局 | 少年抱着师父，问出"接下来我该去哪儿？" | 夕阳竹林，风声萧瑟 |

**特点**：情感饱满，镜头可拉长，意境优先。

#### 方案三：《丹祖转生》（反套路轻松）

炼丹炉成精绑了废柴弟子 → 靠炼丹知识颠覆宗门 → 丹雷渡劫化形。

**特点**：轻松风格，特效密集。

### 2.2 决策过程

用户先选了方案一（凡尘问道），要求我参谋。

我分析后建议方案二更适合入手——因为它：
- 视觉对比丰富（竹屋晨雾 → 山巅残阳 → 废墟煞气 → 竹林对决 → 夕阳落幕）
- 剑作为核心道具贯穿全剧，观众记忆点清晰
- 台词极少（仅 6 句），漫剧靠画面叙事，降低配音门槛
- 最后留白开放，适合做第二集或单集收尾

用户同意，最终选择**方案二《剑意传承》**。

## 4. 第四阶段：理解项目剧本格式（关键转折）

### 4.1 深入阅读项目源码

为了搞清楚项目到底需要什么格式，我阅读了：

**`types.ts`** 中的 `ScriptData` 结构：

```typescript
interface ScriptData {
  title: string;
  genre: string;
  logline: string;
  characters: Character[];
  scenes: Scene[];
  props: Prop[];
  storyParagraphs: { id: number; text: string; sceneRefId: string }[];
  artDirection?: ArtDirection;
}
```

**`services/ai/scriptService.ts`** 中的 `parseScriptToData()`：

- 接受参数：`rawText: string`（原始故事文本）、`language`、`model`、`visualStyle`
- 调用 AI 解析文本为 JSON，提取：title, genre, logline, characters, scenes, storyParagraphs
- 然后自动调用 `generateArtDirection()` 生成美术指导文档
- 再调用 `generateAllCharacterPrompts()` 生成角色视觉提示词
- 再逐个生成场景视觉提示词
- 最后调用 `generateShotList()` 生成分镜头列表

**`components/StageScript/ScriptEditor.tsx`**：

- 就是一个大的 `<textarea>`，placeholder 是"在此输入故事大纲或直接粘贴剧本..."
- 上面有"AI续写""AI改写""提取道具"按钮
- 支持的格式是 Markdown

**`components/StageScript/ConfigPanel.tsx`**：

- 配置项：标题、语言（中文/English/Japanese等）、时长（30s/60s/120s/300s/自定义）、模型选择、视觉风格（7种预设+自定义）

**`components/StageScript/constants.ts`**：

```typescript
export const DEFAULTS = {
  duration: '30s',
  language: '中文',
  model: 'glm-4-flash',
  visualStyle: 'live-action'
};
```

### 4.2 关键理解

项目的工作方式是：

```
用户编写 "故事叙述文本" (rawScript)
    ↓ 点击 "生成分镜脚本" 按钮
parseScriptToData(rawText) 
    ↓ AI 解析
JSON (title, genre, logline, characters[], scenes[], storyParagraphs[])
    ↓ AI 自动
generateArtDirection() → 生成美术指导文档
generateAllCharacterPrompts() → 生成角色视觉提示词
generateVisualPrompt('scene') → 生成场景视觉提示词
generateShotList() → 生成分镜头列表
    ↓ 用户编辑确认
进入 StageAssets 阶段
```

也就是说，我**不需要**提供已经分好镜的分镜头表——我只需要提供一个好的故事叙述文本，让 AI 自己去解析和发挥。

## 5. 第五阶段：为项目编写可解析的源文本

### 5.1 适配项目需求

根据对 `parseScriptToData()` prompt 的分析，AI 期望的输入特征：
1. 包含清晰的**角色描述**（姓名、性别、年龄、性格）
2. 包含清晰的**场景划分**（地点、时间、氛围）
3. 包含**完整的故事叙述**，以段落形式组织
4. 自然语言，Markdown 格式即可

### 5.2 最终交付的源文本

```markdown
# 剑意传承

类型：仙侠 · 师徒 · 传承

## 梗概
大限将至的老剑仙云沧，将陪伴自己六百年的残剑"听蝉"传给了木讷少年阿舟。
剑不肯为云沧出鞘，却在阿舟手中嗡鸣。仇家殷无咎寻上门来，阿舟以凡人之躯拔剑，
一剑惊退强敌。夕阳下，少年抱着师父，第一次问出那句——接下来我该去哪儿？

## 角色
云沧，男，老年。白发白须，青灰布衣，膝上横放一柄残剑。
他已修行八百年，大限将至，面容苍老但眼神平静，看透生死。身体虚弱，偶尔咳血。
阿舟，男，16岁。粗布短打，乱发遮眼，眼神倔强而干净。他话很少，
但有一股不撞南墙不回头的倔劲。
殷无咎，男，中年。黑袍金纹，双手笼袖，煞气外溢。他是云沧的旧敌，
百年未见，如今找上门来寻仇。

## 故事

### 场景一：破旧竹屋 · 黎明
晨雾弥漫的山腰上，有一座破旧的竹屋。竹叶微黄，露珠从叶尖滑落。
屋内陈设简陋，只有一张草席、一方矮桌。云沧盘坐于席上，膝上横放一柄残剑。
剑鞘古朴无华，布满细密的裂纹。他苍老的手缓缓拂过剑身，指尖在裂纹处停留。
他低声自语："修行八百年，到头来最放不下的……反倒是你这块顽铁。"

阿舟跪在门口，低着头，双手攥紧衣角，嘴唇抿成一条线。他已经跪了一夜。
云沧叫他进来，他没有动。云沧又说了一遍，他才抬起头，眼眶是红的。
云沧没有看他，只是握住剑身，用力——剑纹丝不动。
他说："此剑名'听蝉'。我养了它六百年，它不肯出鞘。"
他把剑平举到阿舟面前。阿舟迟疑着抬手，指尖触到剑鞘的一瞬——
剑身微微一颤，发出一声低沉的嗡鸣。云沧的目光动了动，说：
"……看来它等的不是我。"

### 场景二：山巅 · 黄昏
残阳如血，云海翻涌。阿舟在山巅练剑，动作笨拙，一剑砍在空处，整个人差点摔倒。
云沧站在他身后，伸出两根手指，轻轻点在他手腕上，说："剑不是砍的。"

#### 问题分析

逐个字段检查：

  "sceneId": "4",
  "actionSummary": "殷无咎抬手，黑色煞气轰向阿舟，阿舟横剑格挡。",
  "dialogue": "",
  "cameraMovement": "Tracking Shot",
  "shotSize": "Medium Shot",
  "characters": ["1", "2"]   // ❌ 应该是 ["2", "3"]
}
```

- `1` = 云沧（不应该在此场景）
- `2` = 阿舟 ✓
- `3` = 殷无咎（被错误省略）

**根因**：AI 在 `generateShotList()` 的 prompt 中要求使用 character ID（而非名称），但需要人工验证。这个 bug 说明 AI 分镜生成的 characters 字段需要人工审查。

**修复方案**：`["1","2"]` → `["2","3"]`

##### 🟡 中优先级

**3. 高潮镜头缺失**

"剑出鞘·白光冲天·落叶静止"是整部影片最炸裂的视觉高潮。但 AI 的分镜中，这段被压缩在 shot-7 的 actionSummary 里描述，没有独立的关键帧对。

按原设计（18 镜），这段应该有一个**独立的特写→大景镜头**：
- 阿舟爬起 → 说"他在叫" → 剑鞘脱落 → 出鞘 → 白光冲天 → 落叶静止 → 殷无咎震惊

**修复方案**：在 shot-7 和 shot-8 之间插入一个新的镜头。

**4. 分镜数量偏少（10 镜 vs 设计 18 镜）**

AI 生成的分镜算法逻辑：
```typescript
const targetSeconds = 120;  // 2分钟
const totalShotsNeeded = Math.round(targetSeconds / 10);  // 12
const shotsPerScene = Math.max(1, Math.round(totalShotsNeeded / 5));  // 约2-3镜/场景
```

但实际只生成了 10 镜。这对于 120 秒来说略显拖沓（平均 12s/镜头）。

对比原设计（18 镜 ≈ 6.7s/镜头）的节奏更紧凑。

**修复方案**：在 StageDirector 阶段手动补充镜头。

##### 🟢 低优先级

**5. 场景提示词混入水墨词汇**

场景 2（山巅·黄昏）的 visualPrompt 中：
```
在黄昏时分，山巅的景象如同一幅泼墨山水画
```

虽然整体视觉风格是 `live-action`（真人影视），但场景提示词中混入了"泼墨山水画"这种 ink-wash 风格的描述，可能会干扰 AI 生成方向。应改为"黄昏山巅的写实电影画面"。

同样问题也出现在场景 4、5 的 visualPrompt 中。

**根因**：场景提示词由 `generateVisualPrompt('scene')` 生成，它使用的 ArtDirection 可能包含了与视觉风格不一致的语言。

**修复方案**：逐个检查场景 visualPrompt，替换水墨词汇为写实电影词汇。

### 8.2 竹屋·黎明提示词评估

#### AI 原版

> 在晨雾缭绕的山腰上，一座破旧的竹屋矗立。背景是一片朦胧的山林，树木苍翠，
> 竹叶微黄，仿佛被露水洗过，显得格外清新。屋后是连绵起伏的山峦，山间云雾缭绕，
> 增添了几分神秘感。屋前是一片开阔的草地，草地上散落着几块形状各异的石头，
> 石头表面覆盖着青苔，显得古老而沉稳。中景是竹屋，屋檐上挂着几片枯黄的竹叶，
> 屋内透出淡淡的晨光，屋内陈设简陋，但透露出一种古朴的韵味。晨光透过竹叶，
> 洒在屋檐和草地上，形成斑驳的光影。整个场景的色彩以淡雅的土色调为主，
> 辅以柔和的木色调和淡淡的红色，营造出一种宁静而古老的环境氛围。光影交错，
> 营造出一种梦幻般的视觉效果，凸显出场景的神秘和古老。

#### 问题分析

| 维度 | AI 原版 | 应有氛围 | 问题 |
|---|---|---|---|
| 整体氛围 | "清新"、"梦幻"、"神秘" | **苍凉、破败、冷清** | ❌ 云沧大限将至的居所不应该是"清新"的 |
| 光线 | "晨光透过竹叶洒下斑驳光影" | 黎明是雾重、光弱、散射光 | ❌ "斑驳光影"是上午八九点，不是黎明 |
| 色调 | "淡淡的红色" | 冷青灰调，无暖色 | ❌ 黎明是冷色温，不应该有红色 |
| 房屋状态 | "破旧的竹屋"（笼统） | 茅草塌陷、竹墙开裂 | ⚠️ 应具体化破败细节 |
| 屋内容器 | "屋内陈设简陋" | 一张破草席、缺角矮桌 | ⚠️ 应具体到物件 |
| 人气 | "透出淡淡的晨光"（暗示有人） | **没有人气** | ❌ 黎明时分云沧在打坐，但屋内应是无光的死寂 |
| 草地石头 | "石头形状各异表面青苔"（像公园） | 满地落叶+泥土 | ❌ 太整洁了，不像野外的破屋 |

**核心问题**：
1. **氛围基本跑偏**："清新、梦幻、神秘"是旅游宣传片词，不是"大限将至的隐世剑仙的破屋"。应该是"苍凉、破败、寂静、冷清"
2. **光线错误理解黎明**：AI 把"黎明"理解成"阳光斑驳的早晨"，实际上是"浓雾笼罩、光弱对比度低、冷色温散射光"
3. **色调里加了"红色"**：黎明初时是冷青灰，太阳完全升起前不会有暖红色

#### 修正版

> 黎明时分，一座破旧的竹屋孤零零地坐落在山腰上，屋顶的茅草多处塌陷，
> 竹墙泛黄开裂。四周被浓重的**晨雾**笼罩，几米之外的竹林只剩下朦胧的剪影。
> 地面潮湿，竹叶和泥土混杂，**露珠凝结在草尖和屋檐边缘**。
> 屋内没有灯光，只有微弱的天光透过竹墙缝隙渗入，隐约可见一张破草席和一张缺了角的矮桌。
> **没有任何装饰，没有人气**。画面整体为冷青灰调，对比度极低，雾气使远景柔化成一片虚白，
> 只有近处竹屋的轮廓和纹理清晰可见。电影级写实摄影，自然散射光，
> 冷色温，氛围苍凉、寂静，带一丝破败的孤寂感。

#### 修正逻辑

- 删"清新、梦幻、神秘"→ 换成"苍凉、寂静、破败"
- 晨雾从装饰性变成主导视觉元素 → 浓雾笼罩，能见度低
- 光线从"斑驳光影"→ 雾中散射冷光，无直射阳光
- 屋内从"透出晨光"→ 无光，暗示无人气
- 屋况具体化 → 茅草塌陷、竹墙开裂、缺角桌子
- 色调纯净化 → 冷青灰，不要红色

## 12. 经验总结与指南

### 12.1 提示词设计原则（适用于 WL AI Director）

1. **具体 > 抽象**
   - ❌ "眼神透露出煞气"
   - ✅ "脚下的碎石在地面上微微颤动"

2. **道具锚定**
   - 核心道具必须出现在角色的 visualPrompt 中
   - 全剧围绕听蝉剑展开，去掉剑角色就没有辨识度了

3. **姿态固定**
   - 每个角色要有标志性姿态/构图，保持跨镜头一致性
   - 云沧：盘坐抚剑 | 阿舟：握剑倔强站立 | 殷无咎：双手笼袖俯视

4. **氛围用光线写**
   - ❌ "营造一种苍凉的氛围"
   - ✅ "逆光勾勒剪影，冷青灰调，低对比度雾中散射光"

5. **风格纯一**
   - live-action 提示词中不要混入 "水墨""泼墨""写意"等词汇
   - 反之亦然，ink-wash 中不要写 "电影级浅景深"

6. **不要写 AI 不懂的抽象词**
   - 图像模型理解的是：颜色、光影、材质、构图、比例、姿态
   - 图像模型不理解的是：敬畏、执着、决心、命运

### 12.2 AI 解析后的人工审查清单

每次 AI 解析完成后，必须检查：

- [ ] 角色 visualPrompt 是否与剧本设定一致（服饰、道具、姿态、发型）
- [ ] shot.characters 是否使用了角色 ID（而非角色名）
- [ ] 高潮场景是否有独立镜头（不要被塞在其他镜头的描述里）
- [ ] 场景提示词是否与 visualStyle 统一（live-action 不要混入 ink-wash 词汇）
- [ ] 分镜数量是否匹配目标时长节奏（120s ≈ 15-20 镜）
- [ ] 角色 ID 映射是否正确（常见 bug：AI 输出角色名而非 ID）

### 12.3 AI 常见错误模式

| 错误模式 | 示例 | 根因 |
|---|---|---|
| 过度美化 | 阿舟被写成古装男主 | LLM 倾向于把角色美化成"标准模板" |
| 工具缺失 | 云沧没有剑 | LLM 忘记把道具纳入提示词 |
| 姿态模糊 | 殷无咎没有招牌动作 | LLM 未提取姿态关键词 |
| 场景混合 | 黄昏照着"泼墨山水画"描述 | ArtDirection 未有效约束场景提示词 |
| ID 错位 | shot.characters 配错 ID | LLM 混淆了角色名和 ID |
| 物理错误 | 黎明出"斑驳日光" | LLM 对自然现象的理解不够精确 |

### 12.4 后续优化方向

1. **提示词模板化**：建立角色视觉提示词的参数化模板
   ```typescript
   `{name}，{age}，{gender}，{personality}。
    身穿{costume}，手握{prop}，姿态{pose}。
    光线{lighting}，色调{color}，构图{composition}。`
   ```

2. **AI 解析校验层**：在 `generateShotList()` 后自动检查：
   - shot.characters 中的每个 ID 是否存在于 scriptData.characters
   - shot.sceneId 是否存在于 scriptData.scenes
   - 每个 scene 是否至少有一个 shot

3. **ArtDirection 增强**：将角色提示词的修正经验反馈到 `generateArtDirection()` 的 prompt 中，让它在生成美术指导时就更注重服装准确性、道具锚定、姿态固定

4. **物理真实性 check**：对场景的时间-光线关系做规则检查（黎明=无直射光+雾+冷色温，不能出现斑驳光影）

1. **角色形象不统一**：已生成的角色关键帧基于旧版提示词，若直接合成会出现"绣花袍云沧""古装男主阿舟"等偏离设定的形象。建议先完成 §10.4 的角色提示词修正并重新生成关键帧，再做合成。
2. **镜头数不足**：10 镜平均 12s/镜，节奏偏拖。合成前建议补镜（尤其高潮段），使节奏更紧凑。
3. **配音**：剧本台词仅 6 句，可用 Edge-TTS（本地 `:5050`）生成中文配音；或保持默片+字幕风格，靠画面叙事。
