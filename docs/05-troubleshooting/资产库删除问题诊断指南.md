# 资产库删除问题诊断指南

## 问题描述
从资产库删除资产后：
- ✅ 本地 IndexedDB 数据被删除
- ❌ 云端 PocketBase 记录还在
- ❌ 云端文件存储的图片还在
- ❌ 刷新页面后，资产库中还能看到已删除的资产

## 问题原因分析

### 可能的原因

1. **删除 API 调用失败**
   - PocketBase collection 权限规则不足
   - 网络问题导致删除请求失败
   - Token 过期导致请求被拒

2. **删除逻辑不完整**
   - 只删除了本地 IndexedDB，未删除云端
   - 删除云端时出错，但错误被忽略

3. **数据同步问题**
   - 删除后没有刷新本地缓存
   - 刷新页面时从云端重新加载了已删除的数据

## 诊断步骤

### 步骤 1：检查控制台日志

打开浏览器开发者工具（F12），查看控制台输出：

```javascript
// 应该看到的日志（正常流程）
[Storage] 删除素材库项目：{id}
[Storage] 当前在线状态：true
[Storage] 开始从本地 IndexedDB 删除：{id}
[Storage] ✅ 素材库项目已从本地 IndexedDB 删除
[Storage] 尝试从云端删除：{id}
[AssetLibraryAPI] 尝试删除资产库项目：{id}
[AssetLibraryAPI] ✅ 删除成功：{id}
[Storage] ✅ 素材库项目已从云端删除
```

如果看到以下日志，说明有问题：
```javascript
// 错误情况 1：用户未在线
[Storage] ⚠️ 用户未在线，仅删除本地数据，未删除云端数据

// 错误情况 2：删除失败
[AssetLibraryAPI] ❌ 删除资产库项目失败：{id, error, details}
[Storage] ❌ 从云端删除素材库项目失败：{id, error, details}
```

### 步骤 2：检查 PocketBase Admin 控制台

1. 打开 PocketBase Admin UI：`http://127.0.0.1:8090/_/`
2. 进入 **Collections** → `asset_library`
3. 查看删除的资产记录是否还在

如果记录还在，检查：
- **Collection 权限规则**：是否有 DELETE 权限
- **API 规则**：`deleteRule` 是否允许 `@request.auth.id = user_id`

### 步骤 3：检查 Collection 权限规则

在 PocketBase Admin UI 中：
1. 进入 **Collections** → `asset_library`
2. 点击 **Settings**
3. 检查 **API Rules** 部分：

```
listRule:   @request.auth.id = user_id
viewRule:   @request.auth.id = user_id
createRule: @request.auth.id != ""
updateRule: @request.auth.id = user_id
deleteRule: @request.auth.id = user_id   ← 必须有此规则
```

**常见问题**：`deleteRule` 未设置或设置为空，导致删除请求被 PocketBase 拒绝（返回 403）。

### 步骤 4：检查云端文件存储

如果数据库记录删除了，但图片还在：

1. 打开 PocketBase Admin UI → **Collections** → `asset_library`
2. 检查该记录的文件字段是否包含图片
3. PocketBase 在删除记录时会自动清理关联文件（默认行为）

**如果文件未清理**：检查记录删除时是否显式传递了文件删除参数。

## 解决方案

### 方案 1：修复 Collection 权限规则（最可能）

在 PocketBase Admin UI 中：
1. 进入 **Collections** → `asset_library` → **Settings**
2. 确保 `deleteRule` 设置为：`@request.auth.id = user_id`
3. 点击 **Save**

或者通过 pb_migrations 设置：

```javascript
// pb_migrations/xxx_asset_library_rules.js
migrate((db) => {
  const collection = dao.findCollectionByNameOrId("asset_library");
  collection.deleteRule = "@request.auth.id = user_id";
  return dao.saveCollection(collection);
});
```

### 方案 2：添加错误处理和重试

修改删除逻辑，确保失败时抛出错误：

```typescript
// services/hybridStorageService.ts
async deleteAssetFromLibrary(id: string): Promise<void> {
  logger.debug(LogCategory.STORAGE, '删除素材库项目:', id);
  logger.debug(LogCategory.STORAGE, '当前在线状态:', await this.isOnline());
  
  // 从本地 IndexedDB 删除
  await deleteAssetFromLibraryFromDB(id);
  logger.debug(LogCategory.STORAGE, '✅ 素材库项目已从本地 IndexedDB 删除');
  
  // 如果在线，从云端删除
  if (await this.isOnline()) {
    try {
      await assetLibraryApi.delete(id);
      logger.debug(LogCategory.STORAGE, '✅ 素材库项目已从云端删除');
    } catch (error: any) {
      logger.error(LogCategory.STORAGE, '❌ 从云端删除失败:', error);
      throw error; // 抛出错误，让 UI 显示失败提示
    }
  }
}
```

### 方案 3：手动清理数据

如果已经有孤立数据，通过 PocketBase Admin UI 或 API 手动清理：

1. **删除记录**：Admin UI → Collections → `asset_library` → 选择记录 → Delete
2. **清理文件**：PocketBase 在删除记录时自动清理关联文件

   - ✅ 没有错误信息
4. **刷新页面**
5. **检查资产库**：
   - ✅ 已删除的资产不再显示
6. **检查 PocketBase Admin**：
   - ✅ 数据库记录已删除
   - ✅ 存储图片已删除

```
用户点击删除
    ↓
从本地 IndexedDB 删除
    ↓
检查在线状态（应该为 true）
    ↓
调用云端删除 API
    ↓
PocketBase 删除记录（自动清理文件）

```

## 常见问题

### Q1: 删除时提示 403 错误
**原因**：PocketBase collection 的 `deleteRule` 未配置或权限校验失败
**解决**：检查并设置 `deleteRule`（见方案 1）

### Q2: 删除成功但刷新后还在
**原因**：删除的是本地记录，云端未删除
**解决**：检查在线状态和 Token 是否过期（查看控制台是否有 `ensureValidAuth` 刷新失败日志）

### Q3: 数据库记录删除了，但图片还在
**原因**：罕见情况，PocketBase 默认自动清理文件
**解决**：确认记录删除时关联的文件字段被正确处理

### Q4: 控制台显示 "用户未在线"
**原因**：用户未登录或登录已过期（token 超过 7 天且超过 30 分钟无操作）
**解决**：重新登录后再删除
