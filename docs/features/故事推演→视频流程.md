# 故事推演 → 视频流程

## 1 功能概述

「故事推演 → 视频」是一条从单张源图出发、经多阶段 AI 生成最终输出视频的完整管线。用户可在无限画布中选中任意图片，右键启动后经过 5 个步骤完成视频生成：

```
选择图片 → VLM 分析 → 剧情推演 → 宫格生成 → 生成视频 → 完成
```

每个推演会话以**画布图层**的形式存在，支持多会话并行、独立交互，数据随画布项目持久化至 IndexedDB，刷新不丢失。

---

## 2 设计理念

### 2.1 图层化会话

传统做法将生成会话放在独立弹窗中，其状态与画布脱节。本设计将每个推演流程视为一个**画布占位图层**（`type: 'image'` + `operationType: 'story-deduction-flow'`），具有以下优势：

- 多会话并行：同一张源图可发起任意多次推演，每次产生独立图层，互不干扰
- 位置自由：推演图层作为画布元素可自由拖拽、缩放、选中
- 持久化原生：图层数据通过 Zustand Store → IndexedDB 自动持久化，无需额外存储逻辑
- 交互一致：双击/点击推演图层弹出操作卡（FlowOperationCard），与画布其它图层交互范式一致

### 2.2 阶段式管道

流程按阶段严格划分为 5 步（+1 个完成态），每步的输出作为下一步的输入：

| 阶段 | 输入 | 输出 | 数据类型 |
|------|------|------|----------|
| select | 画布所有图片图层 | 选中源图 ID | `sourceLayerId: string` |
| analyze | 源图 | VLM 结构化分析 | `VlmAnalysisData` |
| deduce | VLM 分析 + 叙事方向 | 4 组分镜描述 | `DeductionData` |
| storyboard | 分镜描述 + 源图 | 合成宫格 + 拆分帧 | `StoryboardResultData` |
| video | 拆分帧 + 全部上下文 | 多关键帧视频 | `VideoResultData` |

这种设计使每一步的 AI 结果可被用户审查和编辑，避免黑盒生成导致不可控。

### 2.3 数据即配置

整个 Flow 状态的载体是图层的 `generationPrompt` 字段（JSON 字符串）。这一设计使：

- 推演状态随图层存储，无需独立数据库或 localStorage
- 状态迁移实时反映到画布持久化（Zustand `onChange` → IndexedDB）
- 图层复制、拖拽、分组等操作天然携带完整推演上下文

## 3 UI 交互

### 3.1 入口

画布中选中任意图片图层 → 弹出 `ImageActionMenu` → 点击「推演→视频」

- 触发位置：`src/modules/canvas/components/ImageActionMenu.tsx:184`
- 动作路由：`handleAction` → `onStartFlow?.(layer.id)`
- 不直接启动面板，由 `InfiniteCanvas` 负责创建图层

### 3.2 画布层

- 尺寸：640×320
- 渲染：源图缩略图 + 暗色渐变遮罩 + 推演状态徽章（进行中/已完成）+ 步骤进度条
- 交互：点击（`onClick`）弹出 FlowOperationCard，不是 `onMouseDown`，避免与拖拽冲突
- 源图背景显示：通过 `sourceLayerId` 查找对应的画布图层，取其 `src` 渲染

### 3.3 FlowOperationCard（操作卡）

在画布中单击推演图层时弹出。包含：

| 区域 | 内容 |
|------|------|
| 状态标签 | 进行中（⚡）/ 已完成（✅） |
| 源图缩略 | 从 IndexedDB 解析显示 |
| 进度条 | 5 步线性进度 |
| 视频预览 | 完成后显示缩略图 |
| 继续推演 | 未完成→回到 StoryDeductionFlowPanel 继续编辑 |
| 导出视频 | 完成→将视频导出为新的视频图层到画布 |
| 重新生成 | 完成→重置所有步骤数据回到 analyze 阶段 |
| 删除 | 直接删除推演图层 |

### 3.4 StoryDeductionFlowPanel（主面板）

5 步向导式面板，800px 宽、左侧源图边栏。

- 顶部：步骤编号进度条（圆点+连线）
- 左侧（宽 256px）：源图展示 + 阶梯步骤导航
- 右侧：当前步骤组件
- 每步皆有「上一步」「下一步」（最后一步为「完成」）
- 所有 AI 调用步骤都有「抽卡」（重试）按钮
- 自定义提示词默认可展开编辑

## 4 数据处理流程

### 4.1 启动流程

```
用户点击「推演→视频」
  → ImageActionMenu.handleAction('story-deduction-flow')
  → InfiniteCanvas.handleStartFlow(sourceLayerId)
     ├─ 计算位置：源图层 y + height + 30 + 已有推演层数 * 340
     ├─ addLayer({ type:'image', operationType:'story-deduction-flow', width:640, height:320 })
     ├─ 初始化 FlowState: { phase: 'analyze', sourceLayerId, ... }
     └─ setShowFlowPanel(true), setActiveFlowLayerId(flowId)
```

### 4.2 阶段流转

每个步骤组件（`Step*`）接收 `onSave(data: Partial<FlowState>)` 回调，在保存数据的同时推进阶段：

```
onSave(data) → updateLayer(flowLayerId, { generationPrompt: JSON.stringify(newFlow) })
             → flow.phase 更新为下一阶段 → React 自动切换 renderStep()
```

页面无需手动传递数据；`flow` 对象是整个面板的单一状态来源。

### 4.3 恢复流程

- 未完成：点击推演图层 → FlowOperationCard → 「继续推演」
- setActiveFlowLayerId + setShowFlowPanel(true) → 面板读取 `generationPrompt` 恢复所有状态
- 已完成：「重新生成」→ `fullReset()` 清空 VLM/推演/宫格/视频数据，保留 `sourceLayerId`，回到 analyze 阶段

### 4.4 视频导出

FlowOperationCard.handleExportVideo()：

1. 调用 `unifiedImageService.saveVideoToLocal(videoUrl)` 下载视频并存入 IndexedDB
2. 返回 `video:xxx` 引用
3. 在推演图层下方新建一个 `type: 'video'` + `operationType: 'story-deduction-video'` 的图层
4. 设置 `imageId` 为 IndexedDB 中的视频 ID，确保页面刷新后仍可播放

## 5 数据落地方案

### 5.1 存储架构

```
Zustand Store（内存）
  └─ on change → canvasStorageService（项目级）
       └─ IndexedDB: canvas_projects / canvas_layers 等表
```

### 5.2 推演状态存储

| 载体 | 说明 |
|------|------|
| `layer.generationPrompt` | 整个 FlowState 的 JSON 序列化（约 2-50KB） |
| `layer.operationType` | `'story-deduction-flow'` 标记为推演图层 |
| `layer.sourceLayerIds` | 引用源图层 ID |

### 5.3 图片/视频存储

| 数据 | 存储方式 | 路径 |
|------|----------|------|
| 源图 | 原 `LayerData.src` + `imageId` IndexedDB | 已在画布中 |
| 合成宫格 | `local:xxx` → `imageStorageService` | `StepStoryboard` |
| 拆分帧 | `local:xxx` → `imageStorageService` | `StepStoryboard` |
| 生成视频 | `video:xxx` → `videoStorageService` | `canvasModelService.generateVideoMkr()` |
| 导出的视频层 | `LayerData.src` + `imageId` | `FlowOperationCard` |

### 5.4 刷新恢复

页面刷新 → Zustand Store 重新从 IndexedDB 加载 → 推演图层以普通图层形态出现在画布上 → 点击图层弹出 FlowOperationCard → 重新解析 `generationPrompt` 恢复完整状态

## 6 大模型参与情况

### 6.1 VLM 分析（Phase 2）

- **接口**：`callDramaBackendVLApi()`
- **端点**：`POST /api/v1/generate/image2vl`
- **模型**：Drama Backend 视觉语言模型
- **输入**：源图 URL + 系统提示词 + 用户提示词（从 10 个预设维度自动拼接）
- **输出**：对画面主体、风格、构图、光影、色彩、环境、镜头运动、情感氛围、景深、道具的分析文本
- **容错**：用户可编辑输出结果，支持无限次重试
- **自定义提示词**：用户输入追加在自动生成的维度提示词之后，而非替换

### 6.2 剧情推演（Phase 3）

- **接口**：`chat()` → `callChatApi()`
- **端点**：通用文本对话 API
- **模型**：由后端路由决定（当前为 Qwen 系列或 GLM 系列）
- **输入**：VLM 分析结果 + 用户提供的叙事方向 + 系统角色设定
- **输出**：4 组分镜描述（每组分镜包含景别/机位/主体位置/动作/光影/对白/转场）
- **流程**：LLM 输出 → 按 `---` 分割 → 正则提取字段 → 填入 `StoryboardPanelData` 数组

### 6.3 宫格生成（Phase 4）

- **接口**：`callDramaBackendStoryboardApi()` + `callDramaBackendSpliteGridApi()`
- **端点**：`POST /api/v1/generate/image2storyboard` + `POST /api/v1/generate/image2splitegrid`
- **模型**：Drama Backend 图像生成模型
- **输入**：源图 + 分镜描述 → 2×2 合成宫格图
- **输出**：合成图 (1024×1024) + 4 张独立拆分帧
- **拆分参数**：2 行 × 2 列，目标尺寸由 `IMAGE_SPLITE_GRID` 配置

### 6.4 视频生成（Phase 5）

- **接口**：`canvasModelService.generateVideoMkr()` → `callDramaBackendVideoMkrApi()`
- **端点**：`POST /api/v1/generate/image2videomkr`
- **模型**：Drama Backend MKR 视频生成模型
- **输入**：
  - `images[].src` — 4 张拆分帧（绑定 frame_index 0-3）
  - `prompt` — 4 帧视觉提示的拼接文本
  - `width/height` — 640×360（默认）
  - `duration` — 15 秒（默认，用户可调）
  - `fps` — 30（默认，用户可调）
- **输出**：MP4 视频 → 下载 → 存入 IndexedDB → 返回 `video:xxx` 引用
- **关键帧组装**：`assembleKeyframePrompts()` 将拆分帧、分镜数据、VLM 风格信息、镜头运动等合并为每帧的结构化提示

## 7 类型系统

### 7.1 FlowState

```typescript
interface FlowState {
  phase: 'select' | 'analyze' | 'deduce' | 'storyboard' | 'video' | 'done';
  sourceLayerId: string | null;
  vlmAnalysis: VlmAnalysisData | null;
  deduction: DeductionData | null;
  storyboard: StoryboardResultData | null;
  video: VideoResultData | null;
}
```

### 7.2 子数据类型

| 类型 | 关键字段 |
|------|----------|
| `VlmAnalysisData` | `rawOutput`, `editedAnalysis`, `schema` (aspect→value map), `selectedAspects`, `customSystemPrompt`, `customUserPrompt`, `retryCount` |
| `DeductionData` | `narrativeDirection`, `panels: StoryboardPanelData[]` |
| `StoryboardPanelData` | `shotSize`, `cameraAngle`, `subjectPosition`, `action`, `lighting`, `dialogue`, `transitionToNext` |
| `StoryboardResultData` | `compositeImageUrl`, `splitImages: { gridIndex, src }[]` |
| `VideoResultData` | `keyframePrompts`, `videoUrl`, `thumbnailUrl`, `duration`, `fps` |
| `KeyframePromptData` | `visualPrompt`, `cameraMovement`, `sceneTransition`, `action`, `dialogue`, `timingStart`, `timingEnd` |

### 7.3 图层标记

```typescript
operationType: 'story-deduction-flow'   // 推演流程占位图层
             | 'story-deduction-video'  // 导出的视频结果图层
```

## 8 关键技术决策

### 8.1 为什么选 `generationPrompt` 而非独立存储

- `generationPrompt` 本就是 `LayerData` 内置字段，用于存储生成时的提示词
- 复用该字段存储 FlowState 无需修改数据库 schema
- 推演状态与图层同生命周期，删除图层即删除推演，无需额外清理

### 8.2 为什么不检测重复

设计上允许同一张源图发起多次推演，每次产生独立图层。对用户而言，不同的推演方向（叙事方向不同）应作为独立会话管理。画布中通过图层堆叠位置和标题（「推演→视频 1」「推演→视频 2」）区分。

### 8.3 为什么用 onClick 而非 onMouseDown

画布中图层的拖拽功能依赖于 `onMouseDown`/`onMouseMove`/`onMouseUp` 事件链。如果推演图层使用 `onMouseDown` 打开操作卡，会和拖拽产生冲突：鼠标按下时无法区分是拖拽还是点击。改用 `onClick` 只在完整的点击（mousedown + mouseup，且无位移）时触发。
